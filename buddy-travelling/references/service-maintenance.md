# 服务维护：确认状态、关闭空间、只报变化

本规则优先于本包中“任何未完成都保留/推送”的概括。维护是已确认的服务状态，不是签到成功，也不是数量 0；不根据持续时长改变处理。

## 先判定，再继续业务或收尾

- `maintenance`：目标功能被官网当前维护/升级公告明确阻断，等待首轮 10 秒加载后，间隔 2 秒观察两次一致。未来维护预告、历史公告、聊天/文章/礼物正文中的“维护”字样不算。仅凭空白、超时、缺按钮、登录页或无法读数不能判维护。
- `available`：维护已不再阻断，当前目标功能的真实正常 UI 可用。不能仅凭公告消失、URL 没变、返回 HTTP 200 或重新出现登录页判恢复。继续该 Skill 的原业务流程；保持单次领取/派出和余额核验规则。
- `unknown`：证据不足、登录/网络/读数异常。继续原来允许的恢复操作，仍失败才保留/交接；不把维护记录重置，也不发送“维护结束”。
- Ikuuu 必须先走 workflow 的官网迁移/备用入口队列。一个域名维护而另一个可用，最终是 available，继续签到；全部可信候选实际尝试后，官网明确当前服务维护且没有可用入口，才是 maintenance。单纯所有连接失败仍是 unknown。

## 空间与业务结果

确认 maintenance 后跳过尚未执行的业务，按 task-space-cleanup **立即关闭本轮整个 space 并验证消失**，不要 handOff 或留页等待平台恢复；维护多久都如此。正常 available 也按原门槛关闭。unknown、用户接管和需要人工处理继续按原异常规则保留。关闭失败如实写清理异常，不能假称已关闭。

业务动作已经提交但结果不明时，仍保留原来的“已尝试/结果未确认”和当日禁止重复标记；维护公告不授权重新签到/派出，也不能把未核验业务改写为成功。若此时官网明确维护，可以关闭维护页面并记录 `业务结果未确认（已尝试）`；以后按原来的单次动作门槛处理。

## 持久状态与通知

状态脚本需要 Python 3.9+ 及可读取的 IANA 时区库，用于 `Asia/Shanghai` 时间。
系统未提供该库时（常见于 Windows），部署环境需已有 `tzdata`；缺失时报告依赖问题，
不要在日常任务中自动安装。仓库 CI 安装该测试依赖后运行离线状态测试。

scheduled/自动化每轮收尾后必须调用包内 `scripts/service_health.py`，包括正常轮和 unknown 轮；维护提醒不能凭模型记忆、旧聊天、日期或当轮变量去重。调用前读取本参考。手动/只读查询只关闭已确认维护页面，不调用此通知脚本、不改自动化状态。

```text
python3 -B <本Skill目录>/scripts/service_health.py --phase <maintenance|available|unknown> --page <closed|preserved|unconfirmed|not_created> --space-id <本轮数字ID> --evidence <本轮简短脱敏证据> --detail <本轮实际业务结果> --chat-id <prompt中的lark_chat_id>
```

参数用数组或正确 shell 引号传递，实际执行现成脚本；不要复制实现或自行发送维护正文。脚本只处理状态/通知，**不会替你关闭空间**，必须先完成真实收尾再传 `--page`。维护不得传“签到成功”“待处理 0”，应传“维护中，本轮未执行”或真实已尝试状态。

- 首次 maintenance：记录并通知“维护中”。持续 maintenance：静默，每轮仍关闭。第一次 available：通知“维护结束”，继续原任务；后续 available 静默。
- unknown 不开始/结束维护，不消费待发送状态；独立登录/异常提醒按原规则执行。方舟每轮实际登录提醒仍没有冷却。
- 本机状态默认写到 `$XDG_STATE_HOME/skill-automations/<skill-name>/`（未设则 `~/.local/state/skill-automations/`）；稳定路径跨天使用，禁止加日期/run_id、每轮清空或写入包内。可由部署者用 `--state-dir` 指定稳定的外部目录。它只保存服务状态与通知回执，不是重试调度器、签到/派出账本，也不保存账号或 chat_id。
- 机器人配置默认 `$XDG_CONFIG_HOME/skill-automations/lark-bot.json`（未设则 `~/.config/skill-automations/lark-bot.json`），仅 CLI 路径/profile；也可用 `--config` 指定已有部署配置。目标会话仍只从 prompt 参数传入。不改宿主 OAuth、strict mode 或身份。
- 状态读写带进程锁、原子保存。发送成功且有 message_id 才记已送达。明确发送失败会留下待送事件，由下一次相同状态的正式触发补发同一幂等键；不在本轮循环重发。发送超时/中断/回执不明不盲目补发，报告未确认。新状态取代过时未送事件，恢复时不补一条过时“维护中”。
- 返回 transition=entered/recovered 时，本轮维护通知已由脚本处理；不要再套用通用失败通知。没有变化且 maintenance 时不发送普通失败通知。available 的邀请/低流量/签到异常规则仍有效；已有恢复提醒包含同一业务情况时不得重复推送。
- 通知失败不重开已关闭的空间。状态损坏不自行清空重建；如实报告“维护状态记录不可用”，保留原文件。

## 固定输出

脚本用飞书 post 固定标题和独立段落，字段名加粗：时间、状态、页面、本轮、后续。不要改成分号长句，不附内部命令、推理日志或改进建议。

最终回复统一按 [result-report.md](result-report.md) 渲染，维护结果与通知回执并入那一份短报告，不额外输出服务健康检查段落或脚本 JSON。记录缺失或发送失败不能冒充“已发送”。
