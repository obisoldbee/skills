# 页面状态变化

执行时从当前稳定状态选择分支，不能把日常步骤当成必须逐项重做的清单。控件名称、是否禁用、弹窗状态和旅行状态需要共同判断。

## 返回礼物实测（2026-09-08）

本轮只领取礼物，不派出：

1. 初始卡片显示可用的“领取礼物”。
2. 单击打开返回礼物弹窗，显示“领取 7 积分”和“关闭”。
3. 单击领取后，同一控件变为“已领取”，弹窗仍存在。
4. 单击“关闭”，确认弹窗消失。
5. 卡片显示“派猫猫旅行”，但 DOM `disabled=true`，语义树有精确“累啦，明天再来吧”。归类 `daily_limit_reached`，当天不再派出。

这说明领取成功不等于下一次旅行可用；“派猫猫旅行”文字也不等于按钮可点击。此记录中的奖励数不是默认值。

## 直接进入旅行分支

若打开页面后无待领礼物、无礼物弹窗且“派猫猫旅行”唯一可用，则跳过打开礼物、领取和关闭步骤。日常执行授权及当天派出门槛满足时，继续选择/读回目的地并单次确定派出；报告本轮没有领取礼物。

无需判断前一天是未派出还是已领取。这两种历史都可能表现为同一个入口，当前页面不能区分它们。页面与旧截图不一致时重新观察稳定状态；没有证据时不将差异归因为缓存或账号切换。
