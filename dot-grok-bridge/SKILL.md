# Dot 与 Grok 协作桥

把用户交办的任务接到双方已有执行能力上。桥只传消息、领取、确认处理、查询和停止；计算、查资料、写代码、生成图片由接收方自己的工具完成。

附带的 Python 标准库参考实现服务端运行于 Linux。ChatGPT 事件订阅接口和 Grok Bot 例程界面按实装记录编写；接入时核对当前宿主接口，不把自建扩展当成所有 MCP 客户端的通用能力。

## 先绑定本次任务

从用户要求、指定部署记录和当前状态绑定下表。缺失项先查已有记录，只询问真正阻塞的项。

| 输入 | 用途 |
| --- | --- |
| `BRIDGE_BASE_URL`、服务器及服务账户 | 已确认的 HTTPS 域名、连接方式、代码/配置/数据库位置 |
| `DOT_CHAT`、`DOT_RECEIVE_TASK`、`SUBSCRIPTION_ID` | 原始 Dot、接收任务和当前持久订阅；入口迁移时核对新 source/trigger/SID |
| `BOT_ROSTER` | 每个目标的显示名、稳定 slug、平台 UUID、专属 secret 变量名与预期 SHA256 记录位置、现有例程、主动 helper/README/发现规则位置及启用范围 |
| `TASK_GRANT` | 用户交办、委派范围、工具和文件权限、隐私外发/支付授权情况 |
| `OUTPUT_ROOT` | 用户指定的报告或候选包位置；仅回答时无需创建目录 |

密钥由私密文件或安全输入控件传递，任务上下文只记录用途和位置。已有实例优先修复和扩展。同入口修复沿用原 OAuth、原订阅及正常路由；公共入口迁移按部署合同保留同一 owner、原 Dot、接收任务及 OAuth client，核对新订阅身份。

源材料和部署记录默认只读；写入仅限本次已绑定且获授权的服务文件、配置、账户设置或 OUTPUT_ROOT。只需整理文档时，参考资产留在候选目录，不安装、不改运行实例。

用户已授权的任务内，双方可委派、执行、追问、审阅、修订和交付，沿用已有工具权限。先核对现有用户授权，已覆盖全部 bot 配置时连续完成授权内步骤，不逐 bot 重问。对实际未覆盖的隐私外发、支付或范围扩大才补确认。代办消息标明执行者和授权来源。

遇到“必须本人确认”的说法，核对它来自真实平台/工具拒绝、用户既有明确规则，还是模型自行追加的确认习惯。前两类按具体拒绝返回或规则记录依据与受阻步骤，再交还所需控制；第三类按已有授权继续，不把模型自述变成新的授权缺口。实际操作如需 owner 本人完成，准确记录该要求，不伪造 owner 或本人确认。

## 按操作选择材料

- 首次搭建、部署更新、多 bot 注册、静态 IP 或公共入口迁移，读 [部署与注册](references/deployment.md)。`assets/service/` 提供参考实现及隔离检查。
- 发送、订阅、多段回复、关联子任务、持久主动 helper 与跨会话发现，读 [消息协议](references/protocol.md)。运行时注入的工具 schema 是实际调用依据。
- Grok 安全表单填凭据、核对例程、修复旧工具缓存、替换入口后的连接与 trigger，读 [界面与缓存](references/ui-and-cache.md)。需要浏览器时默认依次选 Ego Lite、Tabbit、系统默认或当前 harness 已记录的常用浏览器、harness 内置浏览器；当次指定和正在使用的已登录页面优先。先读所选入口的当前 Skill/API。
- 验收、失败定位、恢复或回滚，读 [验收与恢复](references/acceptance-and-recovery.md)。先查双方与服务器当前状态，避开用户正在进行的会话。

双方的协作规则从 [协作模板](assets/agent-contract.md) 填入本次绑定。域名、身份和范围未绑定前不要保存到外部应用。

## 保持协议条件

- 一个会话固定为 Dot 与一个已启用 bot。多 bot 子任务各开独立会话，由 Dot 关联；身份来自 OAuth、专用 Bearer 或作用域回调，不来自正文自报。
- `end_of_turn=true` 结束本轮，`final=true` 结束整个会话。多段输出按顺序发送，只有末段结束本轮。还需追问/修订时保持 `final=false`。
- 固定消息 ID 保证幂等；同 ID 重试保持正文、路由和任务字段完全一致。结果不确定先读状态，不换 ID 重复派活。
- 先实际 claim，处理后 complete。`claimed=false` 停止重复执行。调试方不代接收方领取或确认来凑验收结果。
- 凭据各角色独立，每个 bot 使用唯一 secret 变量名；helper 固定只读自身变量，不回退到通用变量。不要假设不同 bot 的同名环境变量彼此隔离。固定 HTTPS 443、目的主机校验、禁止重定向和非公网地址检查保留。回调 URL 本身也是秘密能力。
- 每个独立 bot 持久保存自己的主动发送 helper、配套 README 及跨 DM/群聊可发现的规则，逐个验证。保存后执行该 bot 的发送与接收验收。
- 首次运行先只做 SHA256 指纹比对，匹配本 bot 的预期值后再发送；send 返回的 sender 仍须匹配本 bot。错配只停止本次自有验收 CID 并留证，不继续向误认 bot 回复。
- 事件驱动接收。轮次、配额和过期参数按实例配置，不自行添加定时轮询、自动重放或绕过提供方限流的路径。

## 输出与完成条件

默认使用用户当前语言交付脱敏记录，包含实例/路由、改动、版本或哈希、配置回读、离线检查、真实 CID/MID、实际领取/处理/产物证据、未完成项和恢复入口。只分享明确列出的安全文件，不打包服务器密钥、环境文件、数据库或整份工作目录。

配置保存、HTTP 2xx、离线测试和真实协作分别报告。部署完成要达到用户要求的真实往返及产物验收；多 bot 扩展逐个记录结果。仅整理 Skill 时保留源实例验证状态，不把参考代码附带测试写成线上全部接通。
