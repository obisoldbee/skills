# Ikuuu 浏览器流程

## 1. 当前运行接口

按入口选择浏览器，整轮复用同一目标页面。先核对用户指定或已有的已认证页面及其归属；可继续时直接绑定实际页面标识。需要新建页面时，以下代码仅用于 Ego 路线，先读取当前 ego-browser Skill，再创建一个 TaskSpace 并记录数字 ID；跨 heredoc 用该 ID 恢复。Tabbit 及其他浏览器使用其已提供的页面接口，执行下文相同业务步骤，不调用 Ego 的 TaskSpace 方法。

```js
const task = await taskSpace('ikuuu daily ' + Date.now());
const page = task.page('p1');
console.log({space_id: task.spaceId});
await page.goto('https://ikuuu.win/auth/login');
await page.waitForTimeout(10000);
```

只用当前 `page.url()`、`page.snapshot()`、`page.evaluate()`、`page.click()`、`page.reload()` 和毫秒单位的 `page.waitForTimeout()`。禁止混入旧版 useOrCreateTaskSpace、snapshotText、gotoAndWait、js、wait、cliLog。以当前 snapshot 的 ref 或唯一语义选择器操作，不把 @ref 当 DOM 选择器；快照可在内存内过滤，避免打印账号、邮箱和整页水印。

## 2. 入口发现和站点恢复

目标是完成签到，旧域名列表是发现入口的种子，不是封闭白名单。

- 已绑定有效的已认证页面时直接继续；否则首先访问 `https://ikuuu.win/auth/login`。若页面是“最新域名”“官网迁移”“访问网站”等服务入口页，读取其中实际可见的 HTTPS 链接，优先主域，再备用域。记录来源 URL 与目标 URL；在同一 p1 中继续，不把迁移页判作站点不可达或要求用户先修改 Skill。
- 2026-09-12 实测该页公告日期为 2026-09-11，公布 `https://ikuuu.top/`（主域）和 `https://ikuuu.pw/`（备用）。主域进入 `/user` 并完成签到。日期是历史证据；以后以原官网当前公告或已认证页面“最新官网”的链接为准。
- 已公布的新入口优先于旧备用 `https://ikuuu.fyi/auth/login`、`https://ikuuu.bar/auth/login`、`https://ikuuu.foo/auth/login`。种子失联时，可尝试上述已核验来源的新域和旧备用。不通过搜索广告、未知短链接或猜测相似域名发现登录站点。
- 维护本轮去重候选队列，最多尝试 8 个不同 origin。每次导航先等 10 秒，再判断最终 URL 和页面；仍在加载时最多再等 20 秒。明确网络超时或服务器暂时故障，可在同一站点再试一次；仍失败则继续下一候选。不要把一次超时当成所有站点失败。
- 页面明确“域名不可访问”、DNS/连接失败、服务维护或无可用业务入口：记录该站原因，继续候选。加载正常但结构不熟悉：先检查可见导航、公告链接和必要截图；可恢复就继续，不因选择器失效直接结束。未知页面且没有可信业务入口时记 `unrecognized_page`，不能伪称网络故障；可继续其他已知服务入口，不提交此页表单。
- 实际账号错误、交互验证、安全警告或用户接管不属于域名故障，不换站逃避。浏览器安全警告不绕过；没有安全错误的其他独立官网入口仍可用于连接诊断，但不得重复账号提交。
- 找到可用 `/user` + 首页/签到卡片后停止探测备用域名，继续业务；不要求为了凑满站点数而退出有效登录。
- 全部可用候选都实际尝试后，若官网明确当前服务维护且没有可用入口，走 service-maintenance.md 的 maintenance 分支并关闭；纯连接失败才报告 `site_unreachable`。报告一行“已尝试 origin:结果”，未尝试的不能计为失败。迁移公告仍有未尝试入口时不得结束为全站不可用。

## 3. 登录恢复

`/user` 且可见首页/签到控件：复用登录态，不为测试退出登录。
实际登录页：execute 模式必须尝试现有浏览器认证；query-only 不提交。

1. 等待 10 秒，让已保存凭据加载；不读取、聚焦或修改账号密码字段，也不以 DOM 字段值作为能否点击登录的门槛。
2. 若已显示“验证通过”，直接继续普通登录。若有普通验证入口，按当前所选浏览器工具的验证规则执行并观察最多 20 秒；不要重复点击。实际交互 CAPTCHA/MFA 交接，不模拟解题。若没有验证控件但有正常可用的普通登录按钮，可直接登录；控件是否存在由页面决定，不能要求网站一定长得和旧模板一样。
3. 用最新快照定位唯一普通“登录”按钮（排除标题和 Telegram）。提交一次后等 10 秒，再核验 URL 与首页。成功继续签到；明确账号/安全错误才交接。若是连接失败且可证明提交未发生，可按站点恢复规则继续；提交结果不确定时先观察是否已登录，不重复提交。

## 4. 签到和余额

query-only 仅观察当前状态，记录 `click_attempted:false`；明确可签到时记 before=available、after=not_done，直接读取稳定余额并收尾。以下领取动作仅适用于 execute。

- 本轮尚未点击签到时，页面已经显示“明日再来”：原已签到，跳过签到，继续刷新余额和收尾。若本轮已经点击，按点击前后状态判断，不能再套用原已签到分支。
- 显示唯一“每日签到”：点击一次，观察奖励弹窗和按钮状态；需要时最多再等 10 秒。保存本轮明确奖励，然后关闭成功弹窗的 OK。必须确认“明日再来”；点击超时不能作为再次领取的理由，先重新观察结果。
- 一旦实际调用签到点击，立即在本轮上下文记 checkin_action=clicked_once；后来出现“明日再来”正是可能的完成状态，保留 clicked_once 记录。回顾旧轮时以原始工具调用和回执为准；缺失/冲突则 unknown，不重复签到补证据。
- 调用了 `page.click("text=每日签到", ...)` 就记录 `click_attempted:true`。URL 仍是 `/user` 或变成 `/user#`、调用标签写着“open daily check-in”，都不能证明它只是导航或未执行签到。点击后首次看到的弹窗不能无证据改称进入时已有；缺少点击前快照时填 unknown，保留真实点击记录。
- 本轮没有点击签到，即使进入时已有成功弹窗，也只证明页面已有签到结果：报告“已签到（本轮未重复签到）”，不再另列“领取”。不从余额差、历史报告或旧弹窗推算奖励；仅本轮点击后新出现且关联该点击的成功弹窗可设置 reward_verified:true，金额并入结果行。
- 对当前已认证 `/user` 页面 reload 一次，按 [read-balance.md](read-balance.md) 等待动画稳定。旧选择器失效时重新定位“剩余流量”语义卡片，不读钱包/已用流量，不用动画中间值。
- 刷新出现瞬时加载/读数缺失：先完成最多 30 秒的观察窗口再下结论。确认退出登录或读数仍歧义才报 `uncertain`；保留已核验的签到成功，不重新领取。

## 5. 收尾

按 [task-space-cleanup.md](task-space-cleanup.md) 执行。正常结果和已确认维护先按所选路线完成清理，再通知和简短报告；已签到与低流量也需要关闭。只有完成可恢复分支后仍有未解决异常才保留/交接；明确维护不是此类异常。无人值守不改变正常/异常定义，不能因为 scheduled 就把失败解释成正常关闭，也不能跳过异常通知。
