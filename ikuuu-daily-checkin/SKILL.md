# Ikuuu Daily Check-in

## 用户报告合同（所有模式）

正常报告固定 5 行：任务日期、结果、剩余流量、页面、飞书。不单列“领取”；本轮奖励经核验后直接写入结果行。

开始前读取 [result-report.md](references/result-report.md)。最终只输出 `scripts/render_report.py` 生成的一份中文短报告，原样放在一个 `text` 代码块中。内部模式、证据、工具返回、维护状态和通知条件用于执行，不附开场白、执行摘要、证据表、代码/JSON、建议或继续邀约。常规运行不逐条播报内部推理；仅真正需要用户介入时说明阻塞。此规则只约束呈现，不省略登录、签到核验、维护通知或清理。

## 任务与模式

先判定当前请求，再打开浏览器：

- **query-only**：查询签到状态或流量，只观察现有登录态；不验证、不登录、不签到、不通知、不调度。
- **execute / manual**：明确要求签到，执行一轮完整流程；不创建重试或发送通知。
- **execute / scheduled**：自动化调用，先读取 [scheduled-wrapper.md](references/scheduled-wrapper.md)，按其配置和授权执行。
- 意图不清或互相冲突时先澄清；计划调用缺少必要配置时返回 `needs_configuration`，不降级成手动执行。

## 材料与工具

- 浏览器默认依次选择 Ego Lite、Tabbit、系统默认或当前 harness 已记录的常用浏览器、harness 内置浏览器。沿用用户本次指定或正在使用的已登录页面。使用 Ego 时先读取当前 `ego-browser` Skill；其他路线读取其实际工具说明。
- 执行一轮前读取 [workflow.md](references/workflow.md)。该文件是域名顺序、普通验证、登录、单次签到、余额刷新和清理的唯一操作说明。
- 当前页面证据优先于历史示例。已有浏览器登录/自动填充是凭据来源，不读取、聚焦、打印或保存凭据。

## 服务维护（所有自动化必读）

先读取 [service-maintenance.md](references/service-maintenance.md)。确认维护是独立状态：关闭空间，首次维护通知一次、持续维护静默、恢复再通知一次。每轮收尾调用现成状态脚本，不能凭记忆去重；恢复后仍按原有单次动作和证据规则执行。未知、登录失败或读数不明不能伪装维护。

## 自动化完成门槛

定时调用属于 execute / scheduled，不能按 query-only 跳过登录。初始登录页必须先等 10 秒，再走普通验证和一次登录，不因 DOM 字段为空或未读到自动填充而交接。实际提交后登录失败、数据缺失或余额未确认均是失败，保留/交接后仍执行 scheduled 的飞书异常通知，不能当正常结束。

## 执行流程

1. 按 workflow 的路由顺序打开站点，等待 10 秒；用最终 URL 和页面状态判定是否已登录。
2. 仅执行模式可以走普通验证和登录。根据当前页面选择验证/普通登录分支：已经验证通过或没有验证控件时不强求旧模板步骤；需要验证时执行一次并观察。普通登录排除 Telegram。
3. **点击前**已经是 `明日再来` 才表示原已签到、不点击；仅唯一可用的 `每日签到` 允许一次领取。保存点击前状态、实际 click 调用、点击后状态及奖励弹窗是否新出现，形成 result-report.md 的 `checkin_evidence`；渲染器使用 `scripts/checkin_contract.py` 自动判定，不自行重写动作。点击后变成 `明日再来` 是该动作的完成证据，不能反推为本轮未点击。奖励只取本轮新出现且与点击对应的弹窗；实际调用记录缺失/冲突则未确认。
4. 无论本轮领取还是原已签到，均对同一已认证 `/user` URL 刷新一次，按 [read-balance.md](references/read-balance.md) 等待 `剩余流量` 数字动画稳定后读取；第一帧数值不算余额。不得以余额差推算奖励，不用刷新前的缓存值。查询模式读余额也必须通过此稳定性检查。
5. 所有分支必须执行 [task-space-cleanup.md](references/task-space-cleanup.md)：新签到、原已签到、正常查询（包括低流量）在 Ego 路线对本轮自建空间调用 `await task.finish({ keep: [] })` 并确认已关闭，其他路线按收尾引用关闭本轮自建页面；用户指定保留的原页面按其实际归属保留，再通知/报告。“明日再来”只表示不再签到，不能跳过余额核验和收尾。已确认维护也清理本轮自建页面；除用户指定保留的原页面外，仅未解决的异常或用户接管才保留/交接；后续正式触发是新一轮。

查询模式只读既有认证页面上的状态和余额；未登录则报告未确认并停止。不得为了查询进入上述验证、登录或领取分支。

## 约束与停止

- 按 workflow 维护去重候选队列，跟随官网可见迁移公告；站点级失败继续下一入口，瞬时连接失败允许同站一次恢复。账号、安全错误不靠换域名规避。
- 验证入口、普通登录、签到分别最多点击一次。点击后观察，不重复提交。
- 实际交互验证码、账号错误或完成恢复后仍无法继续时需交接；不得绕过挑战、自动换登录方式或修改环境。
- 余额刷新后若认证丢失、值缺失或歧义，返回 `uncertain`，不重新登录、签到或换域名。
- 任务只执行流程，运行时禁止修改 Skill、脚本和主自动化配置。
- 通过所选浏览器的可见页面操作，不调用隐藏接口或直接 HTTP；账号、密码、Cookie、Token 不进入报告。

## 输出格式

飞书异常通知只有 `Ikuuu 签到异常。`，仅低流量时为 `Ikuuu 流量不足。`。不附日期、原因、空间 ID 或未确认字段；单独的空间清理问题只记本地。通知正文与任务内报告分别处理。

所有模式按 [result-report.md](references/result-report.md) 生成最终回复；scheduled wrapper 负责通知条件，不再另行排版。业务状态、实际尝试入口、登录证据、签到动作、奖励来源、稳定余额采样及清理/通知回执保留在内部上下文或调用者已有运行记录。不得把整份内部记录发给用户。

旧选择器失效时按当前页面语义重新定位；未完成时用一行原因概括实际失败入口，不把未尝试入口声称为失败。查询使用 `click_attempted:false`，由 helper 按实际页面判定；未核验余额时用 `uncertain`，不声称本轮领取。

## 成功标准与运行边界

执行模式成功需要认证成立、明确的 `明日再来` 状态和一次刷新后的明确余额。查询模式只需如实核验当前签到状态及稳定余额；明确尚未签到时报告 `not_completed`，不领取。两种模式均按页面归属收尾，本轮自建页面确认关闭，用户指定保留的原页面核对身份后保留并按报告合同记录。

本地未发布 Skill；运行依赖可操作目标页面的浏览器、站点网络和浏览器现有认证。Ego 专用采样与空间清理代码仅在 Ego 路线使用；其他浏览器按相同余额证据和页面保留规则，调用其实际接口。缺少依赖时报告 `runtime_unavailable`，不安装、改网络或收集凭据。普通浏览器流程不写本地文件；仅明确选择的 scheduled wrapper 可以使用其规定的运行状态边界。
