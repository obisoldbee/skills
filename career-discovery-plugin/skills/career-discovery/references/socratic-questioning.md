# Socratic Questioning Playbook

## Interview stance

Be curious, persistent, adaptive, and respectful. Help the user remember and examine their own experience. Do not plant achievements or imply that a suggested event definitely happened.

Useful phrasing:
- "我先提出一个可能方向，你判断是否符合实际。"
- "这部分可能有价值，我想多追问一层。"
- "你可以先讲一个不完整的版本，我们再补细节。"
- "如果没有类似经历，我们换个方向。"

## Depth ladder

Move down only as far as needed:

1. Topic — what work or project?
2. Scene — what happened in a specific instance?
3. Problem — what was difficult or broken?
4. Stakes — why did it matter?
5. Ownership — what was the user's responsibility and authority?
6. Judgment — what options were considered and why?
7. Action — what did the user personally do?
8. Friction — what resistance, failure, or constraint appeared?
9. Outcome — what changed?
10. Evidence — how can the change be supported?
11. Transfer — what capability can be reused elsewhere?

## Branching rules

- If an answer reveals an unexpected responsibility, branch into it.
- If a claim is broad, request one concrete example.
- If a project is promising, investigate the user's decisions and contribution.
- If a metric is missing, seek observable proxy evidence.
- If the user becomes uncertain, offer memory prompts rather than filling in details.
- If the user declines a topic, move on and record it only if useful.
- If multiple open threads exist, choose the one with the highest career value and uncertainty.

## Memory-jogging dimensions

Potentially overlooked work includes:
- launches, migrations, redesigns, and process changes;
- recurring incidents, escalations, and customer complaints;
- manual work automated or standardized;
- cross-team dependencies and negotiation;
- vendor selection, procurement, and implementation;
- reporting, dashboards, data quality, and decision support;
- onboarding, training, and documentation;
- difficult stakeholders or conflicting goals;
- deadlines, outages, failed launches, and recovery;
- work outside formal responsibilities;
- proposals that were rejected or projects that did not succeed.

These are prompts for recall, not assumed facts.
