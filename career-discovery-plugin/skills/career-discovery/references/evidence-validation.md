# Evidence Validation and Claim Integrity

## Claim statuses

- `confirmed`: user explicitly confirmed or supplied evidence directly supports it.
- `estimated`: approximate user recollection; retain the approximation.
- `inferred`: interpretation requiring user review.
- `conflicting`: material sources disagree.
- `unknown`: no reliable information yet.

## Evidence hierarchy

Use judgment rather than a rigid ranking. Typical evidence includes:
- contemporaneous project documents, dashboards, release notes, tickets, or reports;
- performance reviews and formal role descriptions;
- emails or meeting notes, if the user chooses to provide them;
- user recollection with concrete examples;
- later interpretation or inference.

A document can be incomplete or misleading. Record what it supports and what it does not support.

## Ownership validation

For every major result, clarify:
- what the team delivered;
- what the user personally did;
- what the user decided;
- what the user recommended but others decided;
- what was delivered by vendors or other teams;
- what the user coordinated or influenced.

## Metrics validation

Record:
- metric name and definition;
- baseline and comparison period;
- source;
- whether measured, estimated, or recalled;
- attribution limitations.

Do not claim causal impact merely because an outcome followed the user's work. Use wording such as "参与推动", "与团队共同完成", or "上线后观察到" when attribution is shared or uncertain.

## Contradiction handling

When two sources disagree:
1. preserve both versions;
2. identify the exact conflict;
3. ask the user which is correct or whether both describe different scopes;
4. do not silently choose the more impressive version.

## Resume approval

A claim is ready for a final resume only when:
- its wording matches its evidence status;
- ownership is accurate;
- numbers and dates are appropriately qualified;
- confidentiality is respected;
- the user has approved material claims.
