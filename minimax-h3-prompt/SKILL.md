# MiniMax H3 Prompt

为 MiniMax H3 选择正确创作路线，把实际素材映射为明确角色，并输出可复制的 H3 提示词。本 Skill 自身只准备和审查提示词；不登录账号、不上传素材、不消耗额度、不提交生成任务，也不声称已经生成成功。

若用户在同一请求中还明确要求实际生成，不要把上述边界解释为拒绝整项任务。先完成提示词与输入清单，再由具备执行能力的流程在独立的授权、凭据和付费边界内继续。

输入：用户需求、实际提供的素材、可选的既有提示词，以及已经可靠读取的文件属性。

任务：选择 H3 创作路线，映射素材角色，编写或修订提示词，并指出会阻止提交的未知与冲突。

约束：不猜素材事实，不把案例愿望写成能力保证，不执行账号或生成操作。

输出格式：路由、素材角色、H3 提示词、参数与约束、下一步。

成功标准：路线与素材用途一致，编号可追溯，提示词符合快照限制，未知项原样保留。

语言：说明文字跟随用户；台词、画面文字和提示词语言遵从用户明确要求。

## 先确认边界

- 只有用户明确指向 MiniMax H3、海螺 H3、Hailuo H3，或明确的 H3 视频生成/编辑语境时才使用。不要因孤立出现 `H3` 自动触发。
- 先盘点用户实际提供的素材。文件名、缩略图和用户描述不能证明分辨率、时长、编码、大小或授权状态；未读到的值写 `Unknown`。
- 本 Skill 的数值约束来自 2026-09-02 的官方手册快照。若当前平台是否接受某素材会影响真实提交，提示用户再核对当前界面或 API，不把快照写成永久保证。
- 把“锁脸”“锁动作”“保持不变”视为控制目标，不承诺精确复刻、逐像素不变、文字零错误或口型必然同步。

## 执行流程

### 1. 盘点素材

逐项记录：`@素材编号`、类型、已核实属性、用户指定用途。保留用户编号；没有实际素材时不要杜撰 `@图片1`。

需要完整输入限制时读取 [references/inputs-and-routing.md](references/inputs-and-routing.md)。至少检查：时长、数量、混合素材总数、格式、单文件大小、按入口适用的图片/视频尺寸与比例、提示词长度。音频不能单独作为全能参考输入。

### 2. 选择路线

按以下顺序判断：

1. 有现成视频并要求替换、增加、删除或局部修改：`全能参考（视频编辑）`。
2. 只有一至两张图片，且用户明确它们是开头或结尾关键帧：`首尾帧`。一张图必须说明是首帧还是尾帧；两张图只约束连续补间，不自动设计切镜。
3. 图片承担人物、场景、物体、风格或构图参考，或存在视频、音频、多来源组合：`全能参考`。
4. 没有素材：`文生视频`。

两张“人物图 + 风格图”不是首尾帧。只有音频、混合素材超过 12 个或其他硬约束冲突时标记 `Blocked`，指出冲突并请用户选择；不要擅自丢弃素材。

示例：两张人物/风格参考图走全能参考；只有音频或 13 个混合素材时返回 `Blocked`。更多正反例见 [references/acceptance-cases.md](references/acceptance-cases.md)。

### 3. 映射素材角色

每个用户实际提供且拟作为输入的素材都要写清唯一或有边界的用途，例如：

- `@图片1`：人物身份与服装参考；
- `@图片2`：场景和构图参考；
- `@视频1`：动作与运镜参考；
- `@音频1`：节奏、情绪、音色或待复用音频中的一种。

不要把“节奏参考”“音色参考”“复用原音频”混为一谈。要求复刻歌词、台词、标题、Logo 或界面文字时，必须给出逐字原文；用户未提供时保留为待补信息。

### 4. 写提示词

使用官方三段式：

1. `参考素材说明`：仅列用户实际提供且拟作为输入的素材及其角色；文生视频省略。
2. `核心创意`：用一句话说明主体、地点、事件、题材或风格，以及切镜或特殊运镜策略。
3. `画面过程说明`：按时间或 Shot 写景别、主体、运镜、动作、逐字台词、音效和必要限制。

详细写法见 [references/prompt-workflow.md](references/prompt-workflow.md)。一镜到底写成连续过程，不使用多个 Shot；切镜时重新指明景别和角色；台词长度要适配镜头时长。不要背景音乐时写 `非叙事性音乐：N/A`，不要误写成静音输出。

### 5. 自检并输出

检查素材编号都有角色、路线与素材含义一致、要求之间无冲突、未知项没有被猜测、提示词实际字符数不超过快照上限。不要照搬手册案例中的 `4K/60fps`：规格表写的是 24 FPS 与 768p/1440p，案例目标不是能力保证。

默认使用以下紧凑结构；若 `Blocked`，省略“H3 提示词”，只给冲突和最少的解除方式：

```markdown
## 路由
- 入口：文生视频 / 首尾帧 / 全能参考 / 全能参考（视频编辑） / Blocked
- 理由：仅依据已知素材类型、数量和用途。

## 素材角色
- @素材编号：类型；角色；已核实特征。
- Unknown：尚未核实但影响提交的属性。

## H3 提示词
<可直接复制的三段式提示词>

## 参数与约束
- 已指定：用户明确给出的值。
- 建议值：明确标为建议，不伪装成用户决定。
- Unknown / Conflict：未核实或冲突项。

## 下一步
- 只列阻塞提交或改变路线的最少问题。
```

输出完成或给出 `Blocked` 与最少解除条件后立即停止。不要尝试上传、提交、反复猜测未知属性或替用户选择要删掉的素材。
