# H3 提示词输出工作流

本包支持两种不同的输出面。先选目标，再写一份结果；不要把两套格式叠在同一提示词里。

## Web / App 人工复制

适合用户准备粘贴到海螺网页或 App 的任务。使用飞书手册快照中的三段式：

```text
参考素材说明 + 核心创意 + 画面过程说明
```

### 参考素材说明

只描述用户实际提供且拟作为输入的素材，并给每项素材分配清楚角色：

```text
@图片1 作为人物身份与服装参考。
@图片2 作为夜市环境与色彩氛围参考。
@视频1 仅参考舞步和镜头推进节奏。
@音频1 作为音乐节拍参考，不复用其中人声。
```

### 核心创意

用一句话写清主体、地点、事件、题材或视觉风格，以及是否切镜或采用特殊运镜。把抽象词转换为可见动作、光线、镜头距离和环境反应。

### 画面过程说明

按时间或 Shot 写景别、主体、动作、镜头运动、逐字台词、画内声音和必要限制。一镜到底写成单段连续过程，不使用多个 Shot 标题。

## H3 结构化 Base

适合 API、本地 H3-Base、H3-Context-IR，以及用户明确点名官方 `h3-prompt-writing` 的 T2VA / I2VA / FL2VA / L2VA。

字段顺序固定：

```text
integrated_multimodal_description: ...

overall_soundscape: ...

non_diegetic_music: ...
```

- `integrated_multimodal_description`：沿时间线写视觉风格、初始构图、主体、环境、动作、切镜、说话者、逐字台词和同步画内声音。
- `overall_soundscape`：概括全片环境声、物理动作声和非语言人声；不要重复完整台词。
- `non_diegetic_music`：只写角色听不到、观众听到的背景音乐；没有时写 `N/A`。

关键帧模式在字段前增加对齐说明：I2VA 对齐 0 秒首帧；FL2VA 对齐首帧和最终时刻的尾帧；L2VA 把图片对齐到最终时刻。持续时间使用实际目标时长，不虚构。

对齐说明必须是第一行，随后空一行再写三字段：

- I2VA：声明 `<Picture 1>` 是 `[Shot 1]` 在 `0.00` 秒完整参考的首帧。
- FL2VA：声明 `<Picture 1>` 对齐 `0.00` 秒，`<Picture 2>` 对齐实际总时长 `S.SS` 秒和真正的最终 `[Shot N]`。
- L2VA：声明 `<Picture 1>` 对齐实际总时长 `S.SS` 秒和真正的最终 `[Shot N]`；不要把尾帧误写成 Shot 1。

`[Shot 1]` 不写时间戳。后续切镜使用 `[Shot N] At MM:SS.mmm, ...`，时间严格递增且小于总时长。

## H3 结构化 Ref2VA

适合人物、场景、风格、图片、视频、音频等多来源参考，以及视频编辑。

字段顺序固定：

```text
subject_definitions:
...

summary:
...

retention_analysis:
...

detailed_description:
...

overall_soundscape:
...

non_diegetic_music:
...
```

- `subject_definitions`：定义 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>` 的身份与用途，不把不可见或未核实特征写成事实。
- `summary`：简洁说明目标视频、生成或编辑关系，以及引用素材的作用。
- `retention_analysis`：逐项说明完整保留、部分保留、复制或仅参考的边界，不承诺实际结果必然达到。
- `detailed_description`：沿完整时间线写镜头、主体、动作、引用出现位置、说话者与声音。
- `overall_soundscape` 与 `non_diegetic_music`：沿用 Base 定义。

### Ref2VA 固定标签与关系值

- `<Subject N>`：从参考素材中抽象出的可见人物、物体、场景、服装、动作、构图或风格。
- `<Picture N>`：只有图片本身是首帧、尾帧、关键帧、编辑帧或构图锚点时才单独定义；只提供人物或风格时，应写进对应 `<Subject N>` 来源。
- `<Video N>`：整个视频作为编辑源、续写起点或时间结构来源；视频里的人物、场景和动作仍用 `<Subject N>`。
- `<Audio N>`：确实被复制或参考的音频信号；视频带声音不等于必须创建音频标签。

`summary` 以方括号任务类型开头，只选实际关系并用 ` + ` 连接：`keyframe completion`、`reference generation`、`video editing`、`video continuation`、`audio reuse`、`audio reference`。

`retention_analysis` 使用固定英文关系值：

- 可见内容：`fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`。
- 音频：`fully_copy`、`partially_copy`、`reference`、`weak_reference`。

每个已定义标签在 `retention_analysis` 中各占一行；不要在后续字段引入未定义的新标签。

来自同一视频的 `<Video N>` 和 `<Audio N>` 分别独立编号；普通参考视频仅仅“带声音”不自动产生 `<Audio N>`。只有复制或参考其中音频信号时才定义音频标签。

## 共通写法

### 镜头与连续性

- 切镜后重新指明景别和角色，减少身份与空间漂移。
- 一镜到底不要伪装成多 Shot。
- 首尾帧优先描述可观察的中间变化，不自动增加不相关场景。
- 编辑现有视频时逐条写修改项和保留目标，使用“尽量保持”“相对稳定”等目标描述，不承诺逐像素无损。

### 素材标签

- 网页提示词使用界面的 `@图片1`、`@视频1`、`@音频1`。
- 结构化提示词使用 `<Picture 1>`、`<Video 1>`、`<Audio 1>`、`<Subject 1>`。
- 同一素材在全部段落中编号一致；不要创建没有输入来源的标签。

### 说话者与多语言

- 结构化提示词的说明与字段主体使用英文。
- 台词、歌词、旁白和画面文字保留用户原文与原语言，不擅自翻译或改写。
- 为实际发声者分配稳定 `(S1)`、`(S2)`；不发声的角色不需要说话者编号。
- 结构化台词和歌词使用 `<d>[Language] 原文</d>`；听不清的来源片段写 `[unclear]`，不要猜。
- 台词长度要适配镜头时长。画外音要写清是画外声音，画面中的角色不要被描述为同步开口。
- 画外音必须明确是 off-screen voiceover，并说明对应画面人物嘴唇保持闭合。
- 台词跨切镜时使用 `<scenetrans>` 并说明音频跨镜头连续；视频结束截断话语时使用 `<cutoff>`，不要补写未发生的结尾。

### 声音

- 区分节奏参考、情绪参考、音色参考、复用原音频和画内声音。
- 不需要背景音乐只关闭 `non_diegetic_music`；仍可保留环境声、动作声和对白。
- 未提供逐字歌词或台词时，不把模型代写内容冒充用户原话。

## 冲突自检

- “使用参考音乐”与“无 BGM”冲突。
- “一镜到底”与多个切镜 Shot 冲突。
- 要人物一致却没有人物参考图，是风险而不是可保证结果。
- 要准确文字却没有逐字原文，信息不足。
- 素材编号出现于提示词但不在输入清单中，是错误。
- 结构化字段顺序错误或同时混入网页三段式，是错误。
- 提示词超过 7000 字符，应缩短而不是声称平台会接受。

若文字容易乱码，可以建议把目标文字做成图片素材并声明按图片理解，但这只降低风险，不保证准确渲染。
