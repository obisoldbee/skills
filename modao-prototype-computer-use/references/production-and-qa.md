# 制作阶段与独立质检

创建、还原或完善原型时读取。按当前任务的规模组织阶段，复用已有计划、清单和检查记录。短任务可以只有一个业务段；复杂任务按模块或一组相连状态推进。阶段的产物是实际页面、必要说明和检查结果。

## 分工与模型

| 职责 | 默认模型与等级 | 协作方式 | 交回什么 |
|---|---|---|---|
| 资料整理、业务推理、页面组织与布局决策 | `gpt-6-astra` / `xhigh` | 优先当前聊天子智能体 | 依据、页面及状态范围、必要备注、真实待决问题和可观察的验收条件 |
| 浏览器和桌面 UI 制作、自检及返修 | `gpt-6.1-terra` / `xhigh` | 优先当前聊天子智能体 | 指定原型中的实际修改、保存回读及本阶段所需的预览结果 |
| 独立制作规范质检 | `gpt-6.1-terra` / `ultra` | 默认 `project-handoff`，以 `ego-browser` 检查 | 本阶段实际检查范围、具体缺陷、未核实项及修复后的复核结果 |

这三个默认适用于使用本 Skill 的对应职责。用户本次明确选择的模型、等级、工具及协作方式覆盖对应项；角色合并或续工时保留仍适用的选择。派发时分别核对模型、思考等级和协作方式，按当前工具支持的参数传入。当前聊天子智能体与可见聊天各用所属工具；通过 `project-handoff` 派发时，读取该技能，执行其路由验证、收取结果与负责人质检流程。不要用移动已有聊天的 `handoff_thread` 代替派发。

按当前能力核实精确组合。工具不支持所选模型、等级或协作方式时，说明具体缺项，保留该职责待执行，继续不依赖它的工作；不静默换模型或把自行检查记为独立质检。

## 每个业务段怎样推进

1. **明确这一段要完成什么**。从当前需求、原型和有效参考中确定页面、状态、交互及必要备注。写出看得见的结果，例如新增表单呈现空字段、取消返回原列表、对应备注解释字段规则。把真实业务决策缺口与可直接完成的呈现分开。
2. **先做真实小样**。用一页或一组最小相连状态核对页面内容、原生组件、必要说明、保存回读和所需预览。高保真还原按 [资料对照](reuse-and-note-writing.md#还原当前版本时的资料对照) 执行。完成一处再扩展同类内容，避免错误模板铺满画布。
3. **完成本段并自检**。制作人按 [内容规则](prototype-content-rules.md)、[布局合同](annotation-layout.md) 和 [共同验收](quality-and-recovery.md) 检查受影响页面及相邻布局，修正已发现的问题。只补备注时沿用现有页面；完整制作则补齐范围内必要页面和状态。
4. **交给独立质检**。负责人核对本段实际保存结果，将下节材料交给独立检查者。质检以当前原型为检查对象，先读完整规则和所需正文，再查画面与当前任务所需路径。
5. **修复并重检**。制作人处理具体缺陷，保存并回读；检查者复核修复对象及受影响关系。新改动涉及已检查项时更新对应结论。已通过且未受影响的页面沿用有效检查，避免反复全量重跑。
6. **收回阶段结果并继续**。负责人对照本段目标确认完成范围，更新剩余工作后继续下一段。把已制作、已保存、待独立检查、待修复及已通过的状态写清楚；实际还有工作时保持任务进行中。

用户明确要求先确认小样或计划时，保留该检查点。阶段内已有授权的制作、常规设计、修复与重检直接完成。只读调研不进入制作流程；只读审查按请求观察并返回发现。

## 独立制作规范质检

每段制作完成后安排，最终交付前核对各段覆盖和跨页关系。检查者与制作人分开，负责人收取并检查质检结果，不能只确认对方已启动。 同一任务优先复用已选定的独立检查者逐段复核，交付本段变化与受影响范围；短任务合并为一段即可。已通过且未受本次修改影响的结果沿用原记录。独立质检默认 handoff `gpt-6.1-terra` / `ultra`，使用 `ego-browser` 查看当前原型。先读当前安装的 `ego-browser` Skill，并运行 `ego-browser skill` 获取匹配版本用法。

交接只携带本段需要的信息，至少给出目标原型链接、文件夹/画布/页面范围、当前用户要求及纠正、本 Skill 的实际入口、[内容规则](prototype-content-rules.md)、[布局合同](annotation-layout.md)、[共同验收](quality-and-recovery.md)、本段实际改动及待决项。另附本段用到的原稿、截图或需求依据。制作人的计划和自检可作索引，检查者仍须独立对照这些来源。

沿用当前获准的 Ego 空间及控制权。检查者可以在制作人交出控制后查看同一空间；只有本次已明确允许多个空间时，才在独立空间观察同一原型或预览。按 [Ego 协作规则](ego-browser-workflow.md#绑定已有页面) 执行。制作人暂停本段编辑后交检，检查者以观察为主；修复交回本段唯一编辑者，保存后再交检。原生 App 或其他工具制作的内容也以可访问的同一份墨刀原型为质检对象；暂时无法经 Ego 访问时，明确独立质检未完成。

| 检查面 | 本段通过条件 |
|---|---|
| 页面与状态 | 需求中的页面和关键状态已实际画出，内容及示例相互对应；高保真任务对照有效截图、设计图和当前页面，业务差异有依据 |
| 备注与业务 | 必要字段、操作、计算和状态规则在对应页面可找到，已读卡片和打点正文；真实待决项可定位，产品说明与考点评分分别处理 |
| 组件与布局 | 矩形可自带文字时用单组件；备注就近，引线短直且不交叉，拥挤处已调整页间空间；本期标记色、未决标记及未改内容分别清楚 |
| 画面与路径 | 每个受影响状态按可读比例看过，弹窗、遮罩、裁切、相邻页及连线正常；任务要求可运行时实际走通入口、返回及适用异常路径 |
| 保存与版本 | 观察保存完成后切换返回，必要时重载一次；检查对象与本段交付一致，最后修订影响的结论已经更新；有导出要求时另查最终文件 |

发现问题时给出文件、画布、页面或对象，说明实际现象、违反的具体规则与预期结果，附足以定位的画面或观察。不要只返回一个总分或“建议优化”。范围内可修的问题由制作人直接修复；确有依据缺口、用户禁止修改或工具阻断时，写清未修项、影响和续工入口。未观察的项保留未核实，已知缺陷未修完则本段待修复。

质检输出简短即可，例如“新增供应商页的备注已展开，字段规则齐全；顶部引线穿过表头，需把卡片移到字段上方；修复后重查该页和邻页”。结果能让制作人继续修、让负责人判断本段是否完成即可，不为质检另造冗长报告。

## 长任务的停顿与续工

负责人跟进执行者是否仍在完成当前段。超时、空白画面或一段时间只有记录变化时，先查看实际执行状态、最近工具结果和页面，再决定恢复；按当前工具处理焦点、弹窗、导航或控制权。有效的小样和最后保存位置是续工入口。观察无变化时降低重复检查频率。

执行者受阻时保留具体错误、已保存范围、待检和待修对象；有权限或用户接管提示时按工具停止规则处理。模型或等级不可用按前述分工规则处理。负责人继续可独立完成的内容，避免在页面未完成时以台账增长结束任务。

用户要求暂停时，整理一份足以续工的短记录，包含目标原型、最后已保存页面、阶段状态、未解决缺陷、本期颜色、仍适用的模型分工和下一步动作。用户恢复后先核对当前页面及有效记录，再接着做剩余阶段。最终交付按实际页面、内容、布局、所需预览和独立质检结果判断。
