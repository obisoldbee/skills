# 用实际折点复核引线

能取得本次画面中真实的框、目标和引线位置时，每张独立图片或画布可用一份 JSON 复算。Ego 只读当前界面允许观察的渲染几何；原生桌面可从图上读数。曲线、吸附位置或遮挡读不准时，直接在可读截图上逐条追线，回到[布局验收](annotation-layout.md#交付前逐项判断)。检查小任务无需另量坐标。

从需求和旧说明独立列出应由备注解释的规则（required），然后查看图上每个文字框的全文，把它实际说到的规则号填入 notes。应注清单不能从已有框的数量倒推。每条规则对应一处目标，同组字段可用一个可辨认的目标区域。一条规则需要在两处分别出现时按出现位置各记一项。

所有坐标使用同一张图、同一缩放的整数像素。bounds、targets 中的矩形和每个 box 均为 [左, 上, 宽, 高]，line 从文字框一端依次记录每个真实折点，最后一个点应落在目标处。当前画布内相邻状态页的文字框要一起检查；独立画布各算一次。无业务规则但可能挡住邻线的相邻备注可填空 rules。没有应注规则时由检查者记录实际依据。

在技能根目录运行下列命令，把示例路径换成本次观察记录。

```sh
python3 -B scripts/check_annotation_map.py examples/annotation-map.json
```

输出中，`matched_rule_ids` 只统计规则编号和目标名的对应数。先看 `missing` 是否缺规则，再看 `crossing_pairs` 列出的两条线以及 `issues` 里的错指、裁切、单线自交、折返或穿过自身文字框。同目标的线可以在共同末端相接；沿同一段重叠会报出。框边和线尾容许 2 像素测量偏差，目标在图中还须有可见面积。

退出码 0 表示所给数据里没发现这些问题，1 表示发现缺项或几何问题，2 表示输入无效。最后看图核对正文含义、引线是否遮字穿表、末端能否认出目标。需要能点击时再到预览实点，要求出图时按交付尺寸读最终文件。
