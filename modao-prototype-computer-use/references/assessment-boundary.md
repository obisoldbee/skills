# 原型与考点分开处理

仅在用户要求制作或修改高经等评测考点时读取。日常原型设计遵循 [内容规则](prototype-content-rules.md#哪里必须补备注)，不必运行本文件的考点评审。与评测 Skill 同时使用时，评测规则约束题目、材料和评分；不能把它们的计分筛选条件转成原型备注的删减条件，也不能反过来用设计授权改动正式题面或评分表。

## 两种产物分别判断

先读用户当前要求、全部指定题目材料、原答案及当前原型。对一个内容分别回答：原型是否需要表达；本轮是否有依据将它作为考点。原型必要但题面已明示、属于基础要求、允许多种设计或暂缺唯一政策的内容，仍保留所需说明，不自动计为新增考点。

“原材料没写”既不是设计禁令，也不是扣分许可。合理设计可以补全；不能凭空增设功能并写入答案，再用新增备注证明考点成立。用户选择的编号规则等方案可用于自己的原型，但作答者未收到的私人偏好不得成为隐藏扣分标准。用户当前指定的评分条件和适用的评测规则仍需独立核对，不机械沿用历史题目的政策。

## 分别维护考点和备注

| 原因 | 考点处理 | 原型处理 |
|---|---|---|
| 题面已经直接写明，或与已有考点重复 | 按本轮要求不列新增考点或合并，保留来源 | 必要说明继续保留，重复卡片可合并为可定位的共用说明 |
| 有多种合理设计、没有唯一政策 | 不强制私人方案；是否考察考虑过程按本轮规则判断 | 明确采用方案或真实待决项，不能因无法定唯一标准就省略 |
| 错认当前行为，如把消息里的“修改”当成系统已有订单 | 撤回依赖错误前提的判断 | 删除或改正错误断言；有依据的原文核对需求仍应保留 |
| 凭空添加任务无依据的审计、角色或状态 | 撤回越界要求 | 撤回无依据功能；不能顺带删掉现有流程需要的说明 |
| 当前需求有功能，旧原型没有画 | 先核对当前需求与本轮考察范围 | 完善任务中补上；仅备注任务标明未完成，不称完整原型通过 |
| 用户当前明确排除某流程 | 不针对该流程增设标准 | 本次不实现；旧稿冲突按授权修正或明确标识 |

撤回时指出是“错误业务前提”“本轮范围排除”还是“仅不适合计分”，分别处理。不得把“不新增计分”的结论直接传给录入者作为删卡指令。

## 写法、派工与验收

- 备注写具体业务规则和必要原因；rubric 写考察内容、判断理由及不通过条件。中文润色不改变对象、条件、否定和例外。不要为了同一套句式把评分语混入产品说明。
- 备注计划覆盖本次全部必要说明，关联考点可为 `[]` 或空值；考点列表独立生成。不要求一条备注配一个考点，不为凑数制造功能，也不因考点数量固定而截断备注。
- 业务依据、原型完整性、评分资格、实际写入分别验收。复核原始需求和当前对象，不能只比对同一份计划生成的两个文件是否一致。
- 真实待决备注写明具体缺口；“设计问题已标出”与“已解决”分别报告。考点被删或无新增考点时，仍继续完成授权内的原型工作。
