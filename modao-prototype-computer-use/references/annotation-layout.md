# 备注位置、连线与验收

编辑原型或备注时，制作前和交付前都检查受影响页面的新旧备注，以及相邻页面间的卡片和引线布局。
这些要求来自 [用户的原型设计规则](prototype-content-rules.md#用户的原型布局与组件规则)，不依赖墨刀或某条操作路线。仅记录或仅回答的任务不操作页面。布局工作包含目标画布内为释放备注空间而调整相邻页面位置，保持原页面内容；用户明确固定的页面和范围外画布保持不动。

## 发现问题必须处理

编辑任务中，受影响页面已有的明显缺陷也属于检查和修复责任。发现后必须处理，不能因它早于本轮、没有新增编号或不在录入清单中就跳过。检查延伸到与本次布局相邻、相互影响的页面，不借此重做无关画布。

- 发现空白占位、无效重复卡、错误落点、可避免的长线穿表、交叉、拥挤、遮挡或过远留白，先核实实际对象，再在当前范围内修复并保存回读。不要只把它写成可选建议或推给下一轮。
- 空白卡先通过原生入口展开并读取正文，区分未展开、未加载和真正无内容。确认为无内容且无用途的残留卡，记录位置后清理；有明确用途且材料充分时补全。不得删除尚未读到的说明，也不得为填满卡片编造业务规则。
- 保护旧稿时保留有效业务内容、目标对应关系和未涉及的组件。旧卡的位置、尺寸和引线路径不能一律锁成与编辑前相同；必须允许本次必要的布局修复，再核对修复没有损坏内容。布局修复也按本期颜色规则标记，并在改动记录中说明调整了什么、业务正文是否变化，方便用户检查。
- 派工必须把本条责任和整体验收一并传递。“录入指定条数”只描述计划输入，不能替代质量要求。执行者在分配范围内直接修复；涉及其他执行者负责的对象时，交回具体缺陷，由负责人安排修复并收回验证结果。不得把负责人自行加上的“旧稿全部不动”当成用户限制。
- 只有用户当前明确禁止修改该对象、确实缺少业务决策或工具阻断时，才保留未修项。写明页面、对象、问题、不能修复的实际原因及后续负责事项；继续完成不受影响的部分。未修项保留明确状态。
- 已知缺陷未处理完时，整体状态为未完成。阶段交接可报告已录入部分，但必须同时携带缺陷清单；不得用新增备注通过、保存成功或等待上级验收代替本轮应做的修复。

## 先绑定内容与目标

先按 [哪里必须补备注](prototype-content-rules.md#哪里必须补备注) 检查本次范围的必要说明，确定应补内容，再安排卡片；不只排好已有备注而忽略缺失规则。

- 一条备注说明一组相关规则，指向相关控件、字段或区域。同一对象的默认、联动和校验可放在一张卡内；互不相关的对象或主题拆开。长卡碰撞时按规则关系分组或释放空间，不机械拆成一字段一卡，也不把整页需求塞进一张备注。
- 先读用户现场修改后的内容和布局。记录本次备注的原文、目标、位置、尺寸和样式；保留用户要求保留的示范布局。
- 区分已确认规则、原材料缺口和助手假设。待确认事项写明问题来源及所缺决策，不把自己新增的假设包装成“需业务方确认”。用户已答复后，按最新原话更新确认状态，撤掉过期的待确认表述。
- 真实待确认的文字用警示色并局部加粗；沿用项目已有警示样式，没有现成样式时选清楚可辨的警示色。不要整卡全部加粗，也不把历史项目的精确色值作为固定默认。已确认内容不用未决警示；期次颜色按下节保留，不能随问题确认提前消失。

## 本期改动的颜色

颜色用来帮助用户和开发者找到本期新增、修改的内容。以下是用户对版本协作的明确要求；按本次确定的颜色标记新增与修改。

- 修改前查看原稿配色，并在当前计划或交付说明中定义本期标记色、原有基准色和适用范围。用户指定颜色就使用该颜色；未指定时，选择与已有内容及其他未完成期次清楚区分、文字可读的颜色，说明选择后继续，不为选色单独等待确认。
- 一期任务使用同一标记色。同一期续工沿用已定义颜色，新一期另选颜色；每次接手续工都核对这份定义，不因换执行者或新开聊天自动换色。旧稿有多种颜色时保留其现状，不能为了建立基准把旧内容全染成一种颜色。
- 本期新增和修改的备注都使用本期标记色，未改的备注保持原色。只修改旧卡一部分时，要能辨认改了哪一条；可通过局部标记、合理拆卡或现有变更清单说明，避免把未改条款也说成本次新增。删去或撤回的内容在交付说明中列出原位置和处理结果，颜色不能代替删除记录。
- 页面或组件的改动用关联备注、批注或现有变更记录标明对象和变化，沿用原 UI 的业务配色。不要为标记本期修改，把按钮、表格或整页主题统一改成本期颜色。让用户既能找到本次改动，也能看清具体改了什么。
- 真实待决内容仍使用局部警示色、加粗和明确文字，保持本期标记可辨；不要用整卡警示色覆盖期次信息。工具无法同时表达时，用清楚的文字标识或旁注补充。问题确认后去掉待决标识，本期颜色保留到本期收尾。
- 本期开发已经完成，且当前工作包含收尾整理时，可以把该期标记色归并到约定的原有基准色，保留本期改动记录。用户仍需检查、开发状态未知或只完成原型保存时，先保留本期颜色。归并只处理这一期，不改其他尚未完成期次；原有配色复杂且未约定归并目标时保留现状，并说明未归并的原因。

例如，原稿主要用黄色，当前没有指定其他颜色时，可选一个易区分的颜色标记本期新增与修改。继续同一期任务沿用该色；进入下一期再换色。某条业务问题得到答复，只更新待决状态，不立即把这条改回黄色，以免用户检查时漏掉本期改动。

## 卡片先就近放，再安排引线

### 需要时使用绑定打点

按阅读需要选择外置卡片或原生绑定打点。流程图长说明适合绑定到相关节点，关键分支条件仍留在图中。先在当前版本做一条，确认所属页面和组件、保存后的落点，并在预览中展开全文；页面坐标相近不足以证明已绑定。放点时避开节点文字，复制或移动节点后复查归属。不能把跨页备注的打点集中在第一页。正文、期次颜色与待决标记按本文件共同规则检查；未展开的正文记为未读。

### 外置卡片

1. 按目标在页面中的位置比较上、下、左、右的可用空间。上方目标优先考察上侧，侧边目标优先考察相应侧，底部目标优先考察下侧；由实际空间和整体可读性决定，不固定全部放在页面底部或同一侧。
2. 把目标接近的备注放在一起考虑，错开卡片和连接位置。局部最短线若会与其他线交叉，调整组合布局；不要只逐条贪求最短距离。
3. 引线不交叉，并尽量短直。空间充足时直接连接，不添加无必要的折角；避免长线穿过表格数据、正文或整张页面，不从远端绕回近处目标。先调整卡片位置和顺序解决冲突，不用折线掩盖不合理布局，也不用一条长线代表多个远隔目标。
4. 卡片不得遮挡内容、页面名称、作者区或其他卡片。检查相邻页面之间的空隙，防止本页卡片与邻页备注相碰；检查范围覆盖整个目标画布。
5. 若页间拥挤，把页面及其备注作为布局单元，主动调整目标画布内相邻页面的位置、行列或间距，先释放空间，再安排卡片；保持页内容、名称、流程顺序及连接对应关系。可以结合邻近侧、错位和合理卡片尺寸，不能只缩字、挤卡片或增加折角来绕过页面排布问题。
6. 腾出的空间以清楚容纳页面和备注为度，避免无必要的大空白和过远卡片。调整后仍有真实障碍或拥挤时，才使用必要且尽量少的转折；空间足够仍拐弯不通过。若用户明确固定的布局使问题无法消除，说明具体未通过项，不声称排版完成。

“目标正确”只验证落点，不验证卡片位置或连线路径。不能用“已经连上”“没有交叉”“总长度降低”替代就近与可读性检查。

## 移动与回读

- 文字编辑、卡片移动、端点移动分开操作。先提交并退出文字编辑，再拖标题栏/当前界面确认的移动区域；调整端点时再次确认选中的是该备注的端点。
- 先用一条备注验证本版本的行为，再扩展操作。移动卡片后逐条检查落点仍对应原目标；历史上移动保持落点的成功记录不构成当前版本保证。
- 控件位置或结构改变后重新核对备注目标；保留旧引线但只改文字，可能使它仍指向旧控件。
- 原生吸附会改变实际移动结果。读回最终位置和画面，检查间隙、交叉、遮挡与落点，不能按计划坐标宣布成功。
- Ego 可在当前运行时允许范围内读取渲染几何：区分画布坐标、屏幕坐标和缩放比例；缩放/平移后重新换算。Computer Use 使用可读截图及实际可访问性信息，不要求不存在的 DOM 或几何 API。

## 交付前逐项判断

| 检查 | 通过标准 |
|---|---|
| 完整性 | 已检查涉及页面的新旧卡片、打点正文、操作和主要状态，空白残留及已知缺陷已处理；必要规则已有画面或可定位备注表达，真实未决项明确列出，不按考点数量判断 |
| 内容与状态 | 原话、最新纠正与备注一致；真实未决内容有警示与局部加粗，已解决事项不再待确认 |
| 本期改动 | 已说明本期颜色和原有基准；新增、修改及撤回对象可定位，未改内容未误染色；待决状态与期次可分别辨认，归并未提前进行 |
| 目标 | 每条落点对应其主题；控件移动后已重新检查 |
| 位置与空间 | 卡片就近、间距可读；没有过远留白或拥挤堆叠，四侧布局经过比较 |
| 路径 | 引线不交叉，尽量短直；空间充足没有无必要折角，必要转折有实际障碍依据；无可避免的穿正文/表格或跨整页绕行 |
| 整体画布 | 拥挤处已调整页面排布释放空间；未把卡片推得过远；无碰撞或裁切，页内容、名称、流程顺序和连接关系保持正确 |
| 保存 | 实际保存后切换返回，必要时刷新一次，回读文字、样式、位置及落点 |

每个受影响画布先看整体连线，再按可读比例逐条检查。几何数据与截图互补；未观察的项保留未核实。验收清单必须包含发现的旧缺陷和实际处置，不只枚举新增 ID。任何未解决的上述缺陷都不能交付为“备注排版完成”。在授权内继续修正，再复核受影响部分；不要求每改一条就重跑全部页面。

## 判断示例

- 新增卡片全部合格，旧空白卡或穿表长线仍留在受影响页面里，验收报告只检查新增 ID。整体不通过；核实并处理旧缺陷，复查对应页面。
- 为保护旧正文而要求所有旧引线路径与原稿完全相等。该检查会阻止必要修复；分别验证有效内容保留与修订后的布局正确。

- 卡片上方或侧方留有大片空白，却离所属页面很远：**不通过**；就近排布并缩短引线，节约画布空间。
- 两页之间挤满备注，仅靠缩卡片、缩字或折线容纳：**不通过**；移动相邻页面、调整页间距，再重新排布备注。
- 空间充足但引线仍多次拐弯：**不通过**；改为短直连接。调整页面和卡片后确有障碍的必要转折可以保留，仍须不交叉。

- 顶部筛选框的说明被统一排在页面底部，引线贯穿整张表：**不通过**；应先把卡片安排到顶部或邻近侧，再核对目标与路径。
- 落点在右侧中部，卡片却放到远处右下角并长距离折返：**不通过**；“没有交叉”不能说明布局合理。
- 两条线都很短却互相交叉：**不通过**；联合调整卡片顺序和连接位置。
- 卡片移近后线变短，但端点落到邻列：**不通过**；恢复正确落点后再检查布局。
- 卡片在目标附近、路径清楚、相邻页无碰撞，正文及落点保存回读一致：满足本项布局门槛，仍需完成本任务其他验收。
