# 墨刀原型电脑操作

先辨认用户给的是图片、可打开的原型还是预览链接，再按请求选下面的路线。只审图片直接看图；只读旧稿时可展开批注，交付能定位到页面和控件的发现。用户要求修改时，确认当前文件、画布和允许编辑的对象。同一文件同一时间由一人写入。

## 选任务，读对应指引

| “帮我在预览里复现，第二次打开勾选还在” | [预览与清理](references/functional-interactions.md#预览与清理)、[从正式入口连续做两轮](references/functional-interactions.md#从正式入口连续做两轮) | 实点各个出口，记录使用的值、第一次和第二次的结果。只要求复测时交复现情况，保留现有事件和变量 |

## 操作原型时选界面

| 场景 | 操作依据 |
|---|---|
| Ego 网页 | 读当前 `ego-browser` Skill，运行 `ego-browser skill`，再读 [Ego 操作](references/ego-browser-workflow.md)。绑定当前页面，通过可见控件和鼠标键盘编辑 |
| Computer Use 或原生桌面 | 读当前工具的说明和 [Computer Use 操作](references/native-workflow.md)。用截图、指针、键盘及可用的可访问性信息定位 |
| 需查墨刀的具体功能 | 按功能查阅[官方教程索引](references/official-docs-index.md)，在当前界面确认实际入口 |

沿用用户指定的路线和已有授权。普通网页依次选择 Ego、Tabbit、系统默认或已知常用浏览器、当前环境内置浏览器。权限提示或用户接管按所选工具处理。默认用墨刀原生组件。用户允许其他导入方式时，先用一个小样确认转换后能分别编辑、归属正确、保存后仍在。

## 从制作到验收

每个制作阶段都按上表的分工与共同验收推进。制作人保存回读，负责人收回独立质检结果，修复小样的问题后再扩展同类页面。

1. **先列应注规则。** 从需求、最新纠正与有效旧批注中找出画面没说清楚的条件、动作和结果，各自对应到画布、状态和控件。只补备注时保留原有业务组件与页面。修改旧页而未指定是否覆盖时，先复制原页，在授权副本内处理受保护的原稿。
2. **做一个完整小样。** 沿用项目的原生组件、业务词和排版。选择整页再复制，随即按业务状态命名。分工、模型和等级沿用上表制作指引中的默认值，用户本次指定优先。
3. **每条业务备注用常显、可编辑的文字框加一条原生引线。** 从框边连到具体控件。按目标次序排框，用颜色标期次，需区分读者时把角色写在首行。线相交先调换框位再重连；空间仍挤，在可调整的范围内移动状态页、换行或分画布。旧打点先展开，再把有效说明写入交付图。
4. **逐画布交回实查结果。** 从需求清单逐项找到图上的文字框，沿线追到目标，标出缺注、错指及交叉的两条线。可交互稿开着备注实点落点旁的控件，出图任务重开最终图片。只读审查报告发现；制作人在授权范围内修复并复验。例：“编辑订单／保存。取消后的草稿规则缺注；保存框的线与地址框的线交叉。锁定的邻页未移动。”

## Gotchas · 容易操作错的地方

- 整页常粘贴在右侧。核对选区、组件类型和新页归属再继续。矩形自带文字就沿用单个组件。编辑文字或属性后先提交、退出焦点，再用快捷键。
- 打点编号不能代替正文。逐页打开大画布，等目标区域显示后检查；单页导出容易裁掉页外说明。需要众测读到的全文与引线要在图内。
- 确认页与上一步的按钮可能刚好重合。在演示数据上复点旧坐标，再走正常确认。用户撤回运行要求时，先清本任务的动作，再清变量，并检查复制页是否还留着“未设置”。
- 连续两次操作无效就看当前选区，改从图层或菜单定位。发生误删时撤销或从本次保留的原稿恢复，再核对受影响对象。

交付说明实际画布或图片、完成的检查、待核的具体对象。导出、分享和发布按本次授权执行。
