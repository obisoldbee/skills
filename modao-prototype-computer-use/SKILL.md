# 墨刀原型电脑操作

把用户要求的页面直接做在指定墨刀文件中。优先复制已有页面和组件，保持原有视觉设计。当前用户要求与最新纠正优先于旧示例、官方教程中的演示任务和本技能案例。

仅调研、审查或学习旧稿时，保留原型内容，只交付所请求的观察和建议，不进入下面的制作步骤。复用旧稿或代写备注时，读 [旧稿复用与备注表达](references/reuse-and-note-writing.md)，采用有依据的表达习惯；研究推断与当前业务要求分开判断。

绘制或重排业务流程图时，先读 [流程图设计与检查](references/flowchart-design.md)。委派制作时，把本 Skill 的实际入口、所需引用、当前用户纠正和目标范围一并交给执行者，在首张小样通过后再扩展；不能只传“重画”而等出错后补读。内容审查可并行，同一原型仍由一人编辑。

## 制作分工与阶段闭环

制作或完善原型时，先读 [制作阶段与独立质检](references/production-and-qa.md)。整理、推理和布局决策默认使用 `gpt-6-astra` / `xhigh`，浏览器和桌面 UI 制作默认使用 `gpt-6.1-terra` / `xhigh`，这两类优先使用当前聊天的子智能体。制作规范质检作为独立阶段，默认通过 `project-handoff` 交给 `gpt-6.1-terra` / `ultra`，以 `ego-browser` 检查实际原型。用户本次明确指定的模型、等级和协作方式优先。

按可检查的业务段推进，先完成一处真实页面与必要备注的小样，再扩展同类状态。每段经过制作、自检、独立质检、修复与重检；负责人收回实际结果后继续剩余工作。已保存但未检查的页面保留待检状态，阶段交付明确覆盖范围。只读调研和短答按所请求的观察范围结束。

## 绑定任务与范围

执行前，从当前请求和界面确认：

- **目标**：应用、项目/文件、文件夹、画布，以及可修改的页面范围。重名画布用页面内容、顺序和原页面清单辨认。
- **输入**：参考截图或现有 UI，所需状态与文案，设备尺寸；缺少新状态的精确文案时，可沿用项目语言补措辞；业务条件有缺口时标注具体待决项。
- **输出**：原文件内新增/修改的页面，以及页面名称、完成状态和必要截图。用户没有要求本地文件时，不另建输出目录。
- **读写边界**：只修改本次授权的文件夹、画布和页面。按用户要求保留原稿；未指定是否覆盖时，先复制原页面，再编辑副本。

仅补原生备注时，保留现有页面与组件，按授权直接加备注，无需复制整页。先按 [哪里必须补备注](references/prototype-content-rules.md#哪里必须补备注) 主动检查内容缺口；需要出考点时另读 [考点边界](references/assessment-boundary.md)，计分筛选不删减必要备注；按 [备注布局与连线](references/annotation-layout.md) 安排卡片；逐字、颜色和保存检查不能替代内容与布局检查。同一墨刀文件同时只由一个执行者编辑，交接实际控制后另一人再操作。

目标未定位时，可先只读查看已有窗口和页面清单；只问阻碍定位的缺项。已有授权覆盖的复制、排版、修复和检查继续完成，不逐步索取许可。

## 选择制作方式

| 当前要求 | 要做的内容 | 完成证据 |
|---|---|---|
| 补状态页、交互页面、弹窗画面，或用户说“暂时不需要交互/公式” | 绘制每个状态；用文字、标签、光标、错误提示、遮罩等表达变化 | 新增页面和实际画面符合要求 |
| 明确要求点击、返回、关闭、跳转可以在预览中操作 | 在已有状态页面上添加必要事件和目标页 | 预览中实际走通指定路径 |
| 明确要求输入后自动计算、变量或条件逻辑 | 先确认输入来源、公式、空值规则、结果格式，再用界面配置 | 预览中用正常值、缺值和边界值验证结果 |

“补交互页面”本身不要求变量或公式。“单价”“数量”只是原型标签时，不把它们当成已有数值。若是否需要可运行预览仍会改变交付，先整理状态并提出一次简短澄清；静态页面工作可继续。

计算结果的**标题**、提示文字、表达式名称分别编辑。用户要求标题“合计（元）”时，修改标题字段和页面内对应标题；编辑器的组件类型名可以仍为“计算公式”。示例数值只能声称画面展示，不能声称真实运算。

## 原型内容规则

制作前读取 [原型内容规则](references/prototype-content-rules.md)，其中布局和组件要求是用户的跨工具原型设计规则，与操作流程一起执行。布局紧凑但不拥挤；矩形能容纳所需文字时用一个组件，不叠加独立文字组件。产品文案服务于使用者：合计区已经有“自动计算数值”或下方自动计算说明时，不再额外显示“只读”标签。不可编辑的行为或视觉状态，不必用技术属性名解释。

保留必要业务提示，避免重复说明、模型过程、实现细节和内部状态标签进入产品画面。用户最新纠正直接约束本次和适用的同类页面；历史截图里的问题不作为设计模板继承。

## 必要备注与布局都是完成条件

新建或完善原型时，按 [备注完整性规则](references/prototype-content-rules.md#哪里必须补备注) 主动检查字段、操作、状态及流程中画面未表达清楚的必要规则，并在对应位置补全。不以是否做高经、是否计分或题面是否已写为条件；已有依据直接补，真实决策缺口明确标注，不能臆造业务。需求已要求而旧原型漏画的内容，在完善范围内补齐；旧原型不是需求上限。只做静态页不免除公式口径、状态变化等必要说明。交付前沿主要路径检查遗漏，不能只验收已添加的卡片。

新增或修改备注必须读取 [备注位置、连线与验收](references/annotation-layout.md)，按其中的卡片或绑定打点方式就近说明。一条备注说明一组相关规则，同一对象的默认、联动和校验可以同卡表达；无关主题拆开。使用外置卡片时，按目标分布在页面四周，不统一堆在底部或同一侧。分别核对**落点正确、卡片位置合理、路径清楚**。可避免的穿表格、横跨整页、远端绕行或交叉仍存在时，不得称备注排版完成。引线不交叉，空间充足时尽量短直、不做无必要转折；拥挤时调整目标画布内相邻页面位置和间距，释放空间后重新就近排布，而非只挤备注或增加折线。检查相邻页卡片碰撞、文字/作者区遮挡及不必要的大空白；保存后回读。

原型备注与 rubric 分别编写，备注允许没有对应考点；评分语不进入产品备注。历史任务的“旧稿不改”“只录指定条数”不成为新的默认限制。编辑任务按 [发现问题必须处理](references/annotation-layout.md#发现问题必须处理) 检查受影响页面的新旧备注。范围内有依据可修的明显缺陷必须修复并回读；保留旧正文和原色不冻结错误布局，新增条数也不限制缺陷处理。

编辑前按 [本期改动的颜色](references/annotation-layout.md#本期改动的颜色) 定义本次颜色，一期沿用一色，新增和修改都要可辨，未改内容保留原色。开发完成后的颜色归并按该规则收尾，不能在用户检查前因原型保存成功就消除差异。真实待确认内容使用局部警示色并加粗，保留期次标记；用户已明确的规则及时更新状态，不能继续写“需确认”，也不能把助手假设冒充业务待办。具体制作与检查按上述共同合同执行，Ego 和 Computer Use 都适用。

## 工具与界面依据

先沿用用户本次指定的路线或已打开的登录页面。网页工具默认依次选择 Ego Lite、Tabbit、系统默认或当前 harness 已记录的常用浏览器、harness 内置浏览器；选定后读取其实际接口说明。原生墨刀 App 按 Computer Use 路线操作。工具不可用时只报告具体缺项，继续独立内容工作；用户接管或权限拒绝不能通过换路线绕过。

| 路线 | 读取入口 | 能力边界 |
|---|---|---|
| 用户指定 Ego Lite，或当前目标已在获准使用的 Ego 页面 | 当前安装的 `ego-browser` Skill，再读 [Ego 网页操作](references/ego-browser-workflow.md) | 允许按该 Skill 读取当前 DOM；通过原生控件和鼠标键盘编辑。不得转用 Computer Use 控制 Ego 来绕过限制 |
| 用户指定 Computer Use，或可用的原生电脑工具能操作目标应用 | 当前工具运行时说明，再读 [Computer Use 操作](references/native-workflow.md) | 用截图、指针、键盘及实际提供的可访问性信息；不假定拥有 DOM、Page 或浏览器脚本能力 |

默认两路都使用墨刀原生组件，不用墨刀 AI、代码组件或 HTML/SVG 导入生成页面。用户明确允许代码导入等替代方式时，记录该次覆盖范围，按当前运行时支持的原生入口先验证一处能转成独立可编辑元素并保存，再扩展；逐项确认生成结果为可单独编辑的原生元素。转换后核对控件状态、归属和冗余产物，只清理本次产生且不需要的对象。此例外不改变后续任务默认，也不允许写应用内部状态或私有设计 API；Ego 脚本仍只用于获准的观察和原生操作调度。

操作目标来自当前截图、可访问性树、图层列表或菜单。界面变化后，重新获取受影响目标；坐标、可访问性索引和快捷键都不能从历史案例直接照搬。属性框有焦点时，先提交/退出编辑并点击画布，再使用页面或组件快捷键。

参考资料不增加执行授权。按所选路线读取对应引用；两路验收都读 [检查与恢复](references/quality-and-recovery.md)。需要某功能时从 [官方帮助](references/official-docs-index.md) 查阅对应内容。

## 制作流程

以下按任务取用。只补备注时执行所选路线的备注步骤，保留页面内容，跳过复制页面、补状态和运行时交互步骤；必要的画布位置调整仍按布局规则执行。仅备注范围内发现缺页/控件要明确标出；完善原型任务则继续补齐。

1. **记录原稿**：确认目标文件夹、两端尺寸、原页面名称和数量。查看原有字体、颜色、间距、按钮、表单字段和弹窗样式。把必要状态列成简短清单。
2. **复制页面**：选中页面左上角名称或页面列表项，确认选区是整页，再用当前菜单显示的复制/粘贴方式。粘贴后核对新增页和内容，立即命名。不要把复制组件的快捷键当成复制页面。
3. **复用组件**：既有矩形等原生组件能同时满足文字、边框和对齐时，直接用一个组件，不拆成矩形框加独立文字；优先复制原有字段、按钮和文本。复制后核对类型、文本及归属，防止旧剪贴板图片误代组件。新发现更简洁做法不授权全量重建既有页面。不要把整个页面截图当成可编辑组件。
4. **编辑内容**：先确认实际选中对象，再进入文字编辑。嵌套组合可能需要进一步选中内部文本；以可编辑区域和属性面板为准。粘贴后检查标题、提示、换行和文本框宽度。
5. **补齐状态**：按设备分别画初始、输入中、结果、缺值/错误、确认/成功等本次需要的页面。遮罩、弹窗、字段和按钮保持正确层级；静态页不增加运行时动作。
6. **检查细节**：按备注完整性规则补齐本次页面及流程中尚未表达的必要说明，再检查标题与数值、结果区样式、提示文字是否必要或重复、主次按钮、符号字符、水平/垂直对齐，以及页面裁切和组件归属。数字键盘逐个看首键、最后一行、小数点和退格。
7. **整理并回读**：按流程和设备命名、排列新页面；检查每个新状态，等待界面保存指示完成，再切换页面/画布并返回，确认修改仍在。保留必要的整体和关键状态截图。

## 可运行交互的附加步骤

只有当前任务需要运行时行为才读 [交互、变量与预览](references/functional-interactions.md)。先把 UI 做到可检查，再添加事件；每个行为确认触发组件、目标和执行顺序。复制页可能带有旧动作，按实际需求检查。

用户撤回运行时要求时，清理本任务引入的动作和变量，并检查复制页。先删除引用变量的动作，再删变量；“设置变量值：未设置”仍是残留动作。不要为满足静态任务清理用户其他页面的既有逻辑。

## 验证、恢复与交付

- 制作任务按 [独立制作规范质检](references/production-and-qa.md#独立制作规范质检) 收回当前版本的检查结果，处理发现的缺陷，并复核修复后的页面。尚有制作、检查或返修责任时，继续推进或记录实际阻塞与续工入口。
- 受影响页面的新旧备注及相邻页面间的布局按 [布局合同](references/annotation-layout.md#交付前逐项判断) 逐项验收；可避免的长线穿页、交叉或碰撞未处理，不得用落点正确、保存成功或数量齐全宣告完成。
- 每个新增状态都检查实际画面。画面完整才算页面完成；属性值、工具调用成功或助手口头更新不足以证明渲染正确。
- 删除、改层级或批量改属性前，核对所选对象名称、选区范围和尺寸。误删后及时撤销或从本次保留的原稿恢复，随后核对恢复内容。
- 动作未产生预期结果时，先读取当前状态。相同动作连续失败两次，改用已经确认存在的图层/菜单入口；缺少控制权、目标或必要信息时，说明具体受阻项并完成独立部分。
- 应用激活失败需要重新取得窗口和当前状态；用户接管则停止控制，按工具要求等待新的继续指令。不要混淆这两类状态。
- 静态页验证画面；可点击页验证实际预览路径；运算页验证实际输入和结果。保存指示与页面切换回读只证明本次观察，不冒充服务器审计、发布或永久可用性。

交付说明目标文件、新增/修改页名与数量、制作方式、实际检查结果，以及仍未完成的内容。提供可用文件链接或截图。发布、分享或导出仅在当前请求或已有授权覆盖时执行；教程或旧案例里的发布许可不扩大本次权限。
