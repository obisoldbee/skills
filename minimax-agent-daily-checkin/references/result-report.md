# 执行器回执与短报告

运行入口是 `scripts/run_checkin.py`。浏览器模块自动记录真实空间 ID、逐步观察、领取尝试、积分基线、结果余额和关闭回执；Python 执行器保存通知结果和最终文本。模型不制作 `checkin_input.json`，不从昨天余额拼接本轮证据，不独立运行报告或通知脚本。

## 用户可见结果

正常五行：

```text
MiniMax｜YYYY-MM-DD
结果：签到成功（+N 积分） / 今日已签到 / 今日尚未签到
剩余积分：当前读数
页面：已关闭
飞书：未触发 / 已发送 / 发送失败 / 送达未确认
```

失败保留已确认的业务事实，并增加原因；未关闭时附原空间 ID。页面清理失败不抹去已核验的签到结果，也不单独触发“签到需处理”飞书通知；它属于执行器的本地故障记录。通知已发送不能改成未触发；重复 scheduled 调用原样返回已保存报告。中断后缺少完整证据则报告待核查，不编造剩余积分、成功或关闭。

## 维护者边界

`finish_round.complete` 只供执行器内部使用，校验日期、状态、积分增量和空间字段，然后生成短报告。`finish_round.py` 的 scheduled CLI 不再接收模型手写 JSON。`browser.json` 和 `receipt.json` 是事实记录，既不是可编辑的成功输入，也不是下一次领取许可。

回执只保存必要脱敏信息；不包含账号、电话、UID、凭据、原始登录页、通知目标或个人任务内容。单测使用虚构积分与空间；不能把测试结果当作今天的签到证据。
