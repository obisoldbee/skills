# 定时单轮执行

调用者提供 scheduled 签到请求、`lark_chat_id` 和条件 bot 通知授权，即可执行。缺少配置或授权则停止，不降级手动执行。每次触发读取当前 SKILL.md，再运行一次：

```text
python3 -B <skill_dir>/scripts/run_checkin.py --mode scheduled --chat-id <caller_lark_chat_id>
```

执行器完成建空间、登录、基线、领取、核验、关闭、通知与报告。等待这一个进程结束；后台执行只等待原 session，不再启动一份。不得手写临时 JSON、重新跑报告器、单独创建空间或发送飞书。

## 一次执行和重入

- 日期由系统 Asia/Shanghai 时间决定。当日进程锁阻止并发；完整回执原样返回，保留已发送的真实通知状态。
- 当日已有中断记录时不重开浏览器、不重新领取或盲目重发。输出原空间和已尝试状态，留待核查。
- 正常新签到或原已签到：不发普通结果通知。空间 ID 遗漏、关闭未确认等内部收尾缺陷只记入本轮报告和回执，不包装成“签到需处理”要求用户协助；执行器仍须负责关闭并如实记录结果。
- 确认维护：关闭原空间；维护开始和恢复各通知一次，持续维护静默。未知或登录失败不是维护。
- 签到未完成、登录/环境失败或业务结果未核验：收尾后发一条异常通知；通知回执先保存，再产生最终报告。单独的页面清理异常不触发这条通知。
- 登录尚未完成时不发送“需要登录”；自动登录仍失败才交接原空间并通知。成功登录并完成签到查询后不留一条过时的登录提醒。
- 页面尚未出现账号或登录入口时，先在原页面有界等待约 30 秒，再决定后续动作；登录前重查已登录状态。等待期间继续处理允许关闭的公告；加载未就绪时保留原空间并记录实际阻塞。
- 异常通知只有 `MiniMax 签到异常。` 一句。原因、日期、积分、空间 ID 和未确认项只保留在本地回执；不附在飞书正文。
- 明确的公告、促销和引导弹窗由执行器按可见语义自动关闭并复查，复用原空间继续；不因首次看到广告就通知。整轮最多三个，入口歧义、关闭无效或真实验证/协议仍阻塞时才保留原空间。关闭动作记入当轮回执，不保存弹窗或账号全文。

## 持久边界

包、主调度和身份配置在运行时只读；仅外部状态目录保存运行及通知回执。当前模式不创建提醒、不改变任务频率、不自动重试领取。不要编辑、删除或覆盖旧回执来解锁重跑。

bot 配置默认 `$XDG_CONFIG_HOME/skill-automations/lark-bot.json`（未设则 `~/.config/skill-automations/lark-bot.json`），只含现有 CLI 路径/profile，或由部署者传 `--config`。目标来自调用者参数，不写入包或回执。执行器不改 OAuth、strict mode 或身份；通知失败如实记录，不降级 user，不循环重发。

最终仅将执行器 stdout 放入一个 text 代码块，不复述历史成功，不另造“领取”字段。旧 `finish_round.py --mode scheduled` 已拒绝手填结果，只能由本执行器内部调用报告函数。
