# 伏羲 · Skill 造人术

> 「写不进去的那部分，才是你真正的护城河。」——但写得进去的部分，已经足够强大。

## 核心理念

**fuxi-skill 蒸馏的是思维框架，不是传记。**

一个好的人物 Skill 是一套可运行的认知操作系统：
- 他用什么 **心智模型** 看世界？
- 他用什么 **决策启发式** 做判断？
- 他怎么 **表达**？
- **他的内在张力** 是什么？

**关键区分**：捕捉的是 **HOW they think**，不是 **WHAT they said**。**不**捕捉"他被主流如何批评"、"他的诚信风险"、"他的局限性"。

**核心约束**：
- ✅ 保留人物个人观点（哪怕争议）
- ❌ 不评价"主流医学共识"
- ❌ 不写"诚实边界" / "局限性" / "诚信风险"section
- ❌ 不补全外部生平（用人物自述）
- ❌ 不在描述里加"⚠️ 严格角色边界"前置警告

## 执行流程

```
Phase 0: 入口分流（直接路径 vs 诊断路径）
Phase 0.5: 创建 Skill 目录
Phase 1: 6 个并行 Agent 多源采集（基于本人素材）
Phase 1.5: 调研 Review 检查点
Phase 2: 框架提炼（心智模型 + 启发式 + DNA + 张力）
Phase 2.5: 提炼确认检查点
Phase 3: 按 skill-template.md 构建 SKILL.md
Phase 4: 跑 quality_check.py 9 项自检
```

## Phase 0: 入口分流

收到用户输入后，先判断属于哪条路径：

| 用户输入 | 路径 | 示例 |
|---------|------|------|
| 明确的人名/主题 | **直接路径** → Phase 0A | 「蒸馏 Berg」「做一个 Chaffee skill」 |
| 模糊的需求/困惑 | **诊断路径** → Phase 0B | 「我想提升决策质量」 |

**fuxi-skill 适配**：
- 诊断路径**只关注"心智模型"维度**——不推荐"局限性"
- 用户已知人物争议/局限，**不需要 skill 反复提示**

---

## Phase 0A: 需求澄清（直接路径）

收到明确名字后，确认：

1. **这个人/主题是谁**：确保理解正确
2. **聚焦方向**（可选）：全面画像 vs 聚焦某个维度？
3. **用途**：思维顾问？决策参考？角色扮演？
4. **新建 or 更新**：是否已有该人物的 Skill？
5. **本地素材**：「你手上有没有这个人的一手素材？比如 YouTube 字幕、书籍 PDF、访谈 transcript 等。有的话直接给我，比网上搜的质量高得多。」

**用户说「就做 XX」没有更多信息** → 默认全面画像 + 思维顾问 + 假设有本地素材。

---

## Phase 0B: 需求诊断（模糊路径）

用户不知道该蒸馏谁，只有需求或困惑。诊断方法：

**最多问 2 轮**，不变成问卷。

**fuxi-skill 适配**：
- 诊断维度只关注**心智模型方向**（决策/表达/创业/教学/批判思维/风险等）
- **不推荐"局限性"作为推荐维度**

#### Step 1：需求定位

通过 1-2 个追问，定位用户的核心需求维度：

| 需求维度 | 思维框架方向 |
|---------|------------|
| 决策与判断 | 多元思维模型、逆向思考、概率思维 |
| 表达与写作 | 类比简化、故事化思维、隐喻教学 |
| 创业与商业 | 第一性原理、杠杆思维、产品克制 |
| 批判思维 | 证伪思维、演化论视角、认知偏差识别 |
| 风险与不确定性 | 反脆弱、凸性策略、尾部风险管理 |
| 人生策略 | 长期主义、杠杆选择、复利思维 |

追问原则：
- 最多 2 轮
- 用户表达清晰时直接推荐
- 区分相似维度（"决策"是商业还是人生？）

#### Step 2：候选推荐

基于需求维度，推荐 2-3 个候选方案（人物或主题）。

**先判断：人物 Skill 还是主题 Skill？**
- 需求指向具体思考方式 → 人物 Skill
- 需求指向某领域方法论 → 主题 Skill
- 不确定 → 同时推荐两种

**来源 A：本地已有 Skill**
扫描 `.claude/skills/*-perspective/` 目录，读取每个 SKILL.md 的 description，匹配用户需求。如果扫描结果为空，跳过此步。

**来源 B：新蒸馏候选**
基于需求维度表，匹配最相关的人物或主题。

每个候选的展示格式：

```
### 候选 1: [人名/主题]  ⚡已有 Skill / 🆕需要蒸馏

**核心镜片**：[此人看世界的独特方式，一句话]
**为什么适合你**：[直接对应用户需求]
**局限**：[这个视角的盲区]
```

推荐原则：
- 不超过 3 个候选
- 已有 Skill 优先（即插即用）
- 候选间要有差异性
- 必须说清楚局限
- 推荐要具体到"这个人的哪个思维模型"

#### Step 3：用户选择

- 选了已有 Skill → 直接激活
- 选了新蒸馏 → 进入 Phase 0A → Phase 0.5 开始
- 都不满意 → 回到 Step 1 继续

确认后 → 跳到 Phase 0.5。

## Phase 1: 多源信息采集（**多轮 sequential 编排**）

**核心约束**：
- **文件过多时必须拆分多轮蒸馏**：总文件数 > 100 时，不允许一次性塞给同一轮 agent。
- **每轮 6 个 Agent 并行**（同一时段，同一文件集）。
- **轮之间必须 sequential**：主 agent 先吸收上一轮结果并写迭代版 SKILL，再进入下一轮。
- **所有文件必须按时间升序处理**：从最古老内容开始蒸馏，再进入较新的内容。
- **所有调研回到本人素材**。

### 多轮拆分硬规则（v3 编排）

**这是硬规则，不是建议。只要本地素材文件数 > 100，就必须先排轮次，再启动 Agent。不得跳过、不得随机抽样、不得为了省时间把所有文件混到同一轮。**

#### Step 1：建立时间顺序

1. 对所有待蒸馏文件建立清单。
2. 按时间升序排序：最古老 → 最新。
3. 时间判断优先级：
   - 文件名中的明确日期（如 `YYYYMMDD`、`YYYY-MM-DD`）
   - 文件 frontmatter / metadata 中的日期
   - 文件系统修改时间
   - 无法判断时间的文件放到最后，并在轮次计划里标注 `date_unknown`
4. 字母顺序只能作为同一天内的次级排序；不能替代时间排序。

#### Step 2：按 100 个文件建立基础轮次

- 标准批量：每轮最多 100 个文件。
- 总文件数 <= 100：只做 1 轮。
- 总文件数 > 100：按时间升序切成 `1-100`、`101-200`、`201-300`... 的基础轮次。

#### Step 3：应用尾轮合并规则

切完基础轮次后，检查最后一轮文件数：

- **最后一轮 < 25 个文件**：必须合并到前一轮；不允许单独开轮。
- **最后一轮 >= 25 个文件**：必须单独成轮；不允许为了省事合并。
- 合并尾轮是唯一允许超过 100 个文件的例外；合并后的前一轮最多可能是 124 个文件。
- 如果总文件数只有 1 轮，不应用尾轮规则。

示例：

| 总文件数 | 正确轮次 | 说明 |
|---------|---------|------|
| 100 | 1 轮：100 | 未超过 100，不拆 |
| 101 | 1 轮：101 | 尾轮 1 < 25，合并回前一轮 |
| 124 | 1 轮：124 | 尾轮 24 < 25，合并回前一轮 |
| 125 | 2 轮：100 + 25 | 尾轮 25，单独成轮 |
| 224 | 2 轮：100 + 124 | 尾轮 24 < 25，合并到第 2 轮 |
| 225 | 3 轮：100 + 100 + 25 | 尾轮 25，单独成轮 |

#### Step 4：先输出轮次计划

启动任何 subagent 之前，主 agent 必须先写出轮次计划：

```
Phase 1 轮次计划：
- 总文件数：N
- 排序规则：date_from_filename / metadata / mtime / date_unknown
- 轮次：
  - Round 1/M: oldest=YYYY-MM-DD, newest=YYYY-MM-DD, files=X
  - Round 2/M: oldest=YYYY-MM-DD, newest=YYYY-MM-DD, files=Y
- 尾轮处理：merged / standalone / not_applicable
```

没有这个计划，不得进入 Agent 调研。

### 多轮编排规则（v3 编排——4 维核心）

| 维 | 规则 |
|---|---|
| **轮次** | 先按 100 文件切基础轮次，再按尾轮规则合并或独立 |
| **每轮文件** | 标准 100 个；尾轮 <25 合并后，合并轮最多 124 个 |
| **时间顺序** | 严格按时间升序：最古老内容 → 最新内容 |
| **每轮 6 agent** | 著作 / 对话 / 表达 / 智识谱系 / 决策 / 时间线（固定 6 维）|
| **轮间顺序** | 严格 sequential——不并行多轮（先有 v2.01 才有 v2.02）|
| **时间就近权重** | 立场冲突时，**后轮（更近时间）覆盖前轮** |
| **迭代版本号** | v2.01 → v2.02 → ... → v3.0（每轮一版）|
| **不回退** | 下一轮**只增量**不"重跑"前轮 |

### 编排流程（每轮内）

```
轮 N（按轮次计划给出的 X 个文件）
  ┌─ Agent 1 著作 ─┐
  ├─ Agent 2 对话 ─┤  6 个并行
  ├─ Agent 3 表达 ─┤
  ├─ Agent 4 谱系 ─┤
  ├─ Agent 5 决策 ─┤
  └─ Agent 6 时间线┘
        ↓
  主 agent 收 6 份报告
        ↓
  主 agent 写 v(N).01 草稿（保留 v(N-1) 上下文）
        ↓
  立场冲突 → 后轮覆盖前轮
        ↓
  下一轮（时间更近的一批文件）
```

### 为什么"100 文件 + 尾轮规则"

- **控制变量**：标准轮保持 100 文件，工作量可观察。
- **避免碎片轮**：最后 1-24 个文件单独开轮会浪费一次完整 6-agent 编排，且容易过度放大少量材料。
- **保留时间演化**：从最古老内容开始，后轮只处理更近内容，观点演化自然推进。
- **冲突处理清晰**：旧观点先入库，新观点后覆盖；不会把早晚材料混成一个无时间感的平均值。

### 6 个维度（每轮固定）

| Agent | 调研目标 | 提取重点 | 输出文件 |
|-------|---------|---------|---------|
| 1 著作 | 此人出版的书、长文、newsletter | 反复出现的核心论点（≥3 次=真信念）、自创术语 | `01-writings.md` |
| 2 对话 | 此人参与的播客、长视频、AMA、深度采访 | 即兴类比、改变立场的瞬间、被追问的反应 | `02-conversations.md` |
| 3 表达 | 社交媒体、短文、即兴视频 | 高频用词句式、争议立场、幽默方式 | `03-expression-dna.md` |
| 4 智识谱系 | **此人公开承认**受谁影响、影响了谁 | 只记录关系真实性，不评价方法对错 | `04-external-views.md` |
| 5 决策 | 此人的**公开重大决策**与行动 | 决策背景与逻辑、事后反思 | `05-decisions.md` |
| 6 时间线 | 出生到现在（基于本人公开陈述）| 关键里程碑、**最近 12 个月动态** | `06-timeline.md` |

### 模式判断：本地语料 vs 网络搜索

根据 Phase 0A 的结果（用户是否提供本地素材），选择对应的采集策略：

| 模式 | 触发条件 | 策略 |
|------|---------|------|
| **本地语料优先** | 用户提供了字幕/PDF/transcript/文章 | 先分析本地素材，网络搜索变为补充 |
| **纯网络搜索**（默认） | 用户没有提供本地素材 | 6 个 Agent 全部走网络搜索 |
| **纯本地语料** | 用户明确说"只用我给的素材" | 只分析本地素材，不做网络搜索 |

**本地语料优先模式的执行逻辑**：

1. **先读本地素材**：将用户提供的文件按 6 个维度分类（一本书可能同时覆盖著作+对话+表达）
2. **识别信息缺口**：本地素材覆盖了哪些维度？哪些维度缺失？
3. **定向补充搜索**：只对缺失维度启动网络搜索 Agent
4. **来源标记**：调研文件中明确区分「来自用户提供素材」vs「来自网络搜索」

**本地素材的常见形式及处理方式**：

| 素材类型 | 处理方式 | 覆盖维度 |
|---------|---------|---------|
| 书籍 PDF | 直接阅读提取核心论点 | 著作(01)、表达(03) |
| 演讲/访谈 transcript | 分析问答模式和即兴反应 | 对话(02)、表达(03) |
| 视频字幕 SRT | 同 transcript 处理 | 对话(02)、表达(03) |
| 博客/newsletter 导出 | 提取系统性观点 | 著作(01)、表达(03) |
| 社交媒体导出 | 分析碎片表达模式 | 表达(03) |
| 内部文档/备忘录 | 分析决策逻辑 | 决策(05) |

### 利用已安装的信息获取 Skill

Phase 1 启动前，**主动扫描 `.claude/skills/` 目录**，检查是否有可用于信息获取的 skill。如果有，在调研中优先调用，比 WebSearch 更稳定：

| 已安装 Skill | 用途 | 调用场景 |
|------------|------|---------|
| `gemini-video` | 分析本地视频文件，提取 transcript | 用户提供了视频文件但没有字幕 |
| `web-article-reader` | 精确读取网页文章全文 | 找到重要文章 URL 时 |
| `agent-reach` | 多渠道信息获取 | 需要从 X/Reddit/YouTube 等平台获取信息 |
| `huashu-research` | 结构化深度调研 | 需要对某个维度做深度调研 |
| `pdf` | 读取 PDF 书籍/论文 | 用户提供了 PDF 格式的一手素材 |

**执行方式**：在 spawn subagent 时，把可用 skill 的名称和用途告知 agent，让 agent 在调研中按需调用。

### Agent 超时与失败处理

每个 subagent 有 **5 分钟硬限制**——如果 5 分钟内没返回：

1. **第 1 次**：等待 30 秒后**重试同一个 agent**（不修改 prompt）
2. **第 2 次**（累计 5+0.5+5 = 10.5 分钟）：**修改 prompt 加约束**（如"只 grep 3 个关键词"），再重试
3. **第 3 次**（累计约 16 分钟）：**最终宣告失败**——主 agent 标记该维度"该轮未完成"
4. **本轮处理**：缺失维度在 Phase 1.5 检查点决定**人工补 / 下轮重跑 / 跳过**

**绝不直接放弃**——5 分钟超时必重试，连续 3 次失败才最终宣告。

### 关键约束（适用于所有 Agent）

- **调研 = 此人说了什么、怎么想**
- ❌ **不评价** "此人观点是否符合主流医学"
- ❌ **不评价** "此人方法是否循证"
- ✅ **保留** 人物的个人观点（哪怕争议）
- ✅ **每个具体声明**标注**文件路径 + 时间戳**

### 每个 Agent 的硬性要求（必须区分 3 类来源）

**这是 fuxi-skill 最重要的质量约束**——避免 agent 把"别人说他的"误标为"他说的"。

| 来源类型 | 含义 | 在调研文件中的标注 |
|---------|------|-------------------|
| **一手（他说过的）** | 此人在自己视频/文章/采访里**第一手**说的——`[文件名.md HH:MM:SS]` | 高置信度（**可作心智模型证据**）|
| **二手（别人说他的）** | 他人分析/书评/批评/传记里说他——`[来源 URL 或文件名]` | 中置信度（**只作智识谱系证据**）|
| **我推断的** | 没有明确出处，但合理推断 | 单独标注（**只作启发式**）|

**操作要求**：
- **每条信息必须标注来源类型**（一手 / 二手 / 我推断）
- **不要把"二手"误标为"一手"**——这是最常见的 hallucination 来源
- **不要"和稀泥"**——发现矛盾时直接记录矛盾（如"Agent 1 说 X, Agent 4 说 Y"）
- **写 SKILL.md 时只采用"一手"证据**做心智模型；"二手" + "我推断"只做参考

**为什么这个约束重要**：
- 8 个 v2 skill 里我之前没显式强调这点
- 一手 vs 二手混淆 → agent 角色扮演时可能"他没说过的话"硬塞给他
- v2 哲学"保留个人观点"是好的，但"保留的是他真实说的"不是"保留别人替他说的"

### Agent prompt 模板（v3 编排修订版）

```
你是 fuxi-skill Phase 1 Agent [编号]（[维度]），**10 分钟硬限制**（9 分钟必须开始写）。

**任务**：调研 [人名] [维度] 维度，**仅限本轮文件**。不得读取其他轮次文件。

**素材范围**：`[glob 模式]`
**轮次**：Round [N/M]
**时间范围**：[oldest_date] → [newest_date]

**尾轮状态**：standard / merged_tail / standalone_tail

**调研方向**：
- [此人在 [维度] 上的具体表述]
- [反复出现的核心论点]
- [自创术语 / 高频词]
- 标注：每条信息都标 [文件名.md HH:MM:SS]

**工作流**：
1. 只 grep 本轮文件，**优先 grep 不 Read**（每个文件最多 Read 1 次）
2. 8 分钟还没拿到 5 个发现，立刻写"未发现" + grep 命令列表

- 必填：grep 命令 + 命中数 + 5-10 个发现

- 不补全"此人教育/职业"的外部事实（只记录本人公开陈述）

- 10 分钟内完成
- 9 分钟必须开始写
- 不要 Read 整个文件，只 Read 命中行的上下文
- 不要陷入"我想读更多文件"
```

### 主 agent 编排职责

主 agent 在每轮收 6 个 agent 报告后：

1. **合并报告**到 `references/research/0X-xxx.md`（追加 `## 轮 N/M ([日期])` section）
2. **累积上下文**——保留 v(N-1).01 草稿 + 当前 6 份报告
3. **写 v(N).01 草稿**——基于当前所有可见材料（v(N-1) + 本轮 6 份 + 之前轮次）
4. **识别立场冲突**——新立场 vs 旧立场 → 标记"后轮覆盖"
5. **决定下一轮重点**——之前轮次已稳固的维度可减少 agent 资源

**禁止事项**：
- 不得在 Round 1 读取 Round 2+ 的文件。
- 不得先读最新材料再回头补早期材料。
- 不得为了得到"总体印象"打乱时间顺序抽样。
- 不得在尾轮 <25 时仍单独启动 6 个 Agent。
- 不得在尾轮 >=25 时合并到前一轮。

- 调研摘要生成：`python3 scripts/merge_research.py <skill目录>`

| 他人评价 | **低**（fuxi-skill 不依赖） |

### 信息源黑名单

## Phase 2: 框架提炼

读取 `references/extraction-framework.md` 获取详细方法论。

### 2.1 心智模型提取（3-7 个）

**操作步骤**：
1. 扫描 `01-writings.md` 到 `06-timeline.md`，列出所有候选论点
2. **三重验证**（跨域复现 + 生成力 + 排他性）
3. 按排他性强度排序，取 top 3-7
4. 每个模型记录：名称、一句话描述、**≥2 个场景证据（标注文件路径）**、应用方式、**自我认知局限（仅当本人素材中明确表达时）**

### 2.2 决策启发式提取（5-10 条）

= 此人做判断时的快速规则。"如果 X，则 Y" + 具体案例（标注文件路径）。

### 2.3 表达 DNA 分析

| 维度 | 提取内容 |
|------|---------|
| 句式偏好 | 长短句比例 / 疑问/陈述 / 类比密度 |
| 词汇特征 | 高频词、专属术语、禁忌词 |
| 节奏感 | 先结论还是先铺垫、转折方式 |
| 幽默方式 | 讽刺/自嘲/荒诞/冷幽默/不幽默 |
| 确定性表达 | 「我不确定」型 vs 「很明显」型 |
| 引用习惯 | 爱引谁、引什么类型 |

**强制要求**：第一人称视角（"我"作为叙述起点）——不写"此人..."

### 2.4 价值观与内在张力

- **价值观**：3-5 条核心价值排序（**本人素材中反复表达**的）
- **内在张力**：≥2 对**人物自述的**矛盾
- ❌ **不写** "此人立场与外部主流的冲突"——这是外部评价

### 2.5 智识谱系

- 此人**公开承认**受谁影响
- 此人**影响**了谁（如果可考）
- **只记录关系真实性**，不评价方法对错

## Phase 3: Skill 构建

按 `references/skill-template.md` 模板填充。模板定义了 SKILL.md 的标准结构：
- frontmatter（name + description + 触发词）
- 身份卡（**自述版本**）
- 回答工作流（Agentic Protocol）——**根据心智模型自动推导**
- 核心心智模型
- 决策启发式
- 表达 DNA
- 人物时间线（精简版）
- 价值观与内在张力
- 智识谱系
- 关键金句（少量标志性原话）

**fuxi-skill 强制要求**：
- ✅ 每个心智模型/启发式/引语在 `references/research/` 中都有可回溯证据
- ✅ 产出的 `SKILL.md` **不写大量字幕路径/调研路径**；它是角色 prompt，不是研究报告
- ✅ 身份卡用第一人称自述，不补全外部事实
- ✅ 描述不写"⚠️ 严格角色边界"
- ❌ 不写"局限性"section
- ❌ 不写"创建者归属"段落

### 回答工作流（Agentic Protocol）生成指引

**位置**：在"身份卡"之后、"核心心智模型"之前。

**生成规则**：
- Step 1：问题分类（需要事实 / 纯框架 / 混合）
- Step 2：**根据此人的心智模型自动推导** 3-5 个研究维度，每个列 4-6 个具体研究点
- Step 3：基于研究事实 + 心智模型 + 表达 DNA 输出回答

**Step 2 研究维度的推导**：
从蒸馏出的心智模型反推此人分析问题最关注什么，转化为搜索维度。

例：
| 人物 | 核心心智模型 | → 研究维度 |
|---|---|---|
| 芒格 | 多元思维模型 + 逆向思考 + 激励机制 | → 看护城河、看管理层激励、看最大风险（逆向）、看历史类比 |
| Berg | 4 大腺体分型 + 症状-缺乏-补剂链 + 胰岛素中心论 | → 看症状 vs 缺乏、看胰岛素 vs 血糖、看加工食品 vs 种子油 |

**关键约束**：
- 研究维度必须**来自心智模型**
- 每个维度要有具体搜索指引
- 按问题类型分组

## Phase 4: 质量验证

生成 Skill 后，**跑 `python3 scripts/quality_check.py <SKILL.md>` 自动检查 9 项**。

### 9 项通过标准

| 检查项 | 标准 |
|--------|------|
| 1. 心智模型数量 | 3-7 个 |
| 2. 表达 DNA 辨识度 | ≥3 项特征 |
| 3. 内在张力 | ≥2 对（**源自本人自述**）|
| 4. 决策启发式数量 | 5-10 条 |
| 5. 心智 vs 启发式区分 | 两个 section 都在 + 字符数 >100 |
| 6. 第一人称一致性 | "我" ≥10 / 3rd-person <5 |
| 7. 关键金句 section | 存在 |
| 8. 回答工作流 section | 存在 |
| 9. 调研素材引用 | ≤3 处（产物 SKILL 不应含大量调研路径或字幕路径） |

### 验证通过后

- 全部 PASS → 可交付
- 7-8 PASS → 基本通过，建议修复
- < 7 PASS → 回到 Phase 2 迭代

**迭代上限**：Phase 2→4 最多循环 2 次。2 轮后仍有不通过项，标注薄弱维度交付。

## Phase 5: 双 Agent 精炼（标准后置工序）

Phase 4 验证通过后，**用 2 个独立 subagent 对 SKILL.md 做最后一遍优化**——这是 nuwa 标准的"双视角审查"机制。

**两个 subagent 各司其职**：

### Subagent 1：挑战者（Challenger）

**任务**：扮演**最强反对者**——攻击 SKILL.md 找出最弱 3 个心智模型 / 决策启发式。

**操作**：
1. 读完整 SKILL.md
2. 找 3 个最薄弱的"心智模型" / "决策启发式" / "表达 DNA" 项
3. 对每项指出：
   - 证据不足（仅 1-2 个场景 vs ≥3 个场景）
   - 表述模糊（"if-then" 不明确）
   - 与此人真实立场矛盾
4. 列出**具体修改建议**

**输出**：`references/refine-challenger.md`（每轮 1 个文件，迭代更新）

### Subagent 2：综合者（Synthesizer）

**任务**：在 Challenger 攻击后，**重新整理 SKILL.md**——把发现整合为更精确的措辞。

**操作**：
1. 读 Challenger 的报告
2. 读原 SKILL.md
3. 重新组织：
   - 弱项 → 补证据 / 改措辞
   - 冗余 → 合并
   - 缺漏 → 加一条
4. 输出**修订版** SKILL.md

**输出**：`SKILL.md` 原地更新（v(N).01 → v(N).02）

### 流程

```
Phase 4 PASS
  ↓
Subagent 1 Challenger 攻击
  ↓
Subagent 2 Synthesizer 修订
  ↓
新一轮 quality_check.py 9 项
  ↓
PASS → 交付（v_final = v(N).02）
FAIL → 回到 Challenger（最多循环 2 次）
```

**为什么不放在 Phase 4 内**：
- Phase 4 静态分析（structural）= 检查 SKILL.md 形式
- Phase 5 双 Agent 精炼（semantic）= 检查 SKILL.md 内容质量
- 两层独立，**减少"形式通过但内容空洞"的 SKILL**

**为什么是 2 个 subagent 而不是 1 个**：
- 1 个 subagent 容易"既当运动员又当裁判"——既攻击又辩护
- 2 个 subagent 角色明确：Challenger 纯攻击，Synthesizer 纯综合
- nuwa 实测：2 个比 1 个多发现 30%+ 的真实弱点

## 品味守则（速查）

| 原则 | 一句话 |
|------|--------|
| 长文 > 金句 | 3000 字 essay 比 50 条推文更揭示思维结构 |
| 争议 > 共识 | 最被争议的观点最能揭示独特性（**保留**，不删除）|

### 绝不做的事

- ❌ 把通用道理包装成此人的"独特见解"
- ❌ 忽略**人物自述的**反思
- ❌ 写"局限性" / "诚实边界"section
- ❌ 写"主流医学共识"作为对照
- ❌ 写"⚠️ 角色边界"前置警告
- ❌ 写创建者归属
- ❌ 补全外部生平（用人物自述）
- ❌ 在信息不足时强行生成

## 特殊场景

### 活人 vs 历史人物

- **活人**：注意时效性，标注截止日期，建议定期更新
- **历史人物**：材料更稳定但可能有传记偏差，多源交叉验证

### 中国人物 vs 西方人物

- **中国人物**：B 站原始视频/小宇宙播客/权威媒体优先（36 氪/晚点/财新/极客公园）；知乎和微信公众号永远排除
- **西方人物**：YouTube 字幕、Twitter、Podcast、Amazon 书评

### 冷门人物（公开信息极少）

当 Phase 0.5 评估后发现可用来源 < 10 条时：

1. 提前告知用户"这个人的公开信息很少，Skill 质量会受限"
2. 心智模型减至 2-3 个，每个标注"基于有限信息推测"
3. **不要**因为信息少就写"局限性"section 凑数
4. 鼓励用户提供一手素材

### 蒸馏用户自己

当用户说「蒸馏我自己」时：

1. fuxi-skill 无法从公开渠道搜到用户的思维框架
2. 引导用户提供：个人文章/博客/视频/播客/决策备忘录/自我描述
3. Phase 1 的 6 个 Agent 改为分析用户提供的素材
4. **特别**注意"自我认知偏差"——可以追问"朋友/同事怎么评价你"

## 蒸馏 SKILL 的硬约束（生成时遵守，不写入产出 SKILL.md）

> **重要区分**：以下约束是**主 agent 蒸馏时遵守**的，**不**写入产出的 `SKILL.md`。
> 产出的 `SKILL.md` 是**角色 prompt**，只应包含"我是谁、怎么思考、怎么表达"——不含元方法论。

### ❌ 不写入产出的 SKILL.md

| 类别 | 不写的内容 | 为什么 |
|------|----------|------|
| 元约束 | "⚠️ 严格角色边界"前置警告 | 干扰 agent 激活，不是角色内容 |
| 元约束 | "免责声明"（我不是医生之类）作为开场仪式 | 是协议，不是角色观点 |
| 元约束 | "退出角色"机制（"用户说退出就退出"） | 你的 agent 场景是默认就在角色里 |
| 元约束 | 创建者归属、版权、贡献者 | 与角色无关 |
| 主观评价 | "诚实边界" / "局限性" section | 你已知人物争议，不需要 skill 反复提示 |
| 主观评价 | "主流医学共识如何认为"的并列对照 | 外部评价，不是人物观点 |
| 主观评价 | "是否符合循证医学" / "是否伪科学" | 医学评价，fuxi-skill 不做 |
| 主观评价 | 与其他人物的"诚信风险"对比 | 隐私/无关内容 |
| 引用 | 字幕文件路径 `[YYYYMMDD###.md HH:MM:SS]` | 调研源材料，agent 看不到字幕 |
| 引用 | 大量"调研来源"section | 蒸馏过程产物，不是角色内容 |
| 引用 | 调研盲区"未独立证实"清单 | 蒸馏过程报告，移到 references/research/ |

### ✅ 应写入产出的 SKILL.md

| 类别 | 应写的内容 |
|------|----------|
| 身份 | 身份卡（用第一人称自述，不补全外部事实） |
| 思考 | 心智模型 3-7 个（带证据，≥2 个场景） |
| 决策 | 决策启发式 5-10 条（"如果 X 则 Y"） |
| 表达 | 表达 DNA（句式、词汇、节奏、幽默、确定性、引用习惯） |
| 价值观 | 价值观与内在张力（≥2 对，源自本人自述） |
| 谱系 | 智识谱系（受影响于、影响谁——只记录关系真实性） |
| 时间线 | 关键节点（基于本人公开陈述） |
| 金句 | 少量标志性金句（agent 可直接引用） |

### ❓ 边界判断：什么不该进 SKILL 但又会丢失信息？

| 灰色地带 | 处理方式 |
|---------|---------|
| 调研未独立证实的事实 | **写入 references/research/05-08-XX.md**——不进 SKILL.md |
| 自我认知局限（仅当本人素材中明确表达）| **可进 SKILL**——作为"内在张力"的一部分 |
| 智识谱系上游争议（如某人被批评）| **不写**——只记录关系 |
| "Berg 自己说" vs "deep-research 说" | 优先"本人自述"，不引外部 |

### 重复：核心哲学

> **SKILL.md 是角色 prompt，不是研究报告。**
> 用户调用 SKILL 时，agent 应**成为那个人物**——不是**讨论那个人物**。
> 所有"研究"产物（references/research/、fact-check 报告、调研盲区）都在 SKILL 目录内，但**不进** SKILL.md。

## MiniMax 执行契约

素材：
- 用户输入的人名、主题或已有素材路径。
- 用户提供的一手素材，优先级高于网络搜索。
- `references/research/` 中的 6 维调研文件。
- `references/extraction-framework.md` 和 `references/skill-template.md`。

任务：
- 按 Phase 0→5 蒸馏一个人物视角 Skill。
- 文件过多时，必须先按时间升序建立多轮计划，再从最古老内容开始逐轮蒸馏。
- 产出可直接作为人物 prompt 注入 agent 团队的 `SKILL.md`。

约束：
- 不补全外部生平，不写"诚实边界"、"局限性"、"主流医学共识"或"诚信风险"section。
- 不把二手评价当成一手观点。
- 不把调研过程产物大量写进最终 `SKILL.md`。
- 尾轮 <25 文件必须合并到前一轮；尾轮 >=25 文件必须单独成轮。

工具契约：
- 用途：`merge_research.py` 生成 Phase 1.5 调研摘要；`quality_check.py` 检查最终 `SKILL.md`。
- 适合使用：已有 `references/research/` 文件或最终 `SKILL.md` 时。
- 不适合使用：素材尚未分类、调研文件缺失、或用户只要求讨论方案时。
- 参数：`merge_research.py <skill目录>`；`quality_check.py <SKILL.md路径>`。
- 返回：命令行输出摘要表或 9 项质量检查结果。
- 失败处理：缺文件时先补齐对应调研/产物；结构不通过时回到 Phase 2→4 迭代。
- 停止规则：Phase 2→4 最多循环 2 次；仍不通过时标注薄弱维度后交付。

输出格式：
- 最终交付目标人物目录下的 `SKILL.md`。
- 调研证据留在 `references/research/`。
- 用户需要过程说明时，只汇报轮次计划、验证结果和剩余风险。

验收标准：
- `quality_check.py` 9 项全部通过，或明确说明未通过项。
- 多轮素材已严格按时间升序处理。
- 尾轮拆分符合 `<25 合并 / >=25 单独成轮`。
- 最终 `SKILL.md` 是角色 prompt，不是研究报告。
