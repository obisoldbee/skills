# 每日领取 AI 应用积分

默认检查 WorkBuddy、TRAE CN、Qoder CN、豆包工作和 ZCode。开始前按本次用户指令或定时任务提示确定应用、账号和动作。被排除的应用整项跳过，保持其运行状态。每日任务对每款应用先打卡并核实领取结果，再检查更新，有新版就安装。用户明确指定仅领取时省略更新步骤。用户仅要求查询时，只观察授权范围内的状态，不领取、更新或切换未授权账号。通过当前可用的电脑操作工具与应用界面交互，以本次可见状态为准。

## 执行顺序

1. 每次执行先读取当前机器实际使用的本文件。使用无需打开或接管窗口的应用清单，按下列 bundle ID 记录本次范围内每个应用的运行状态，以及清单能提供的窗口显示状态。打开豆包工作后、切换前记录其原来的当前账号。初始状态不明时标为未知，保留其运行及无法恢复的窗口状态。使用「豆包工作」的 bundle ID 或准确路径。
2. **每次只操作一款应用**。筛选后依次处理 TRAE CN、Qoder CN、豆包工作、ZCode，WorkBuddy 在本次范围内时放最后。选取每款前记录本地时间，完成当前应用的操作及收尾后再选取下一款。读取辅助功能树或截图也可能接管窗口。
3. 对当前应用记录每个账号的本次新增数量、领取结果和最新余额；可刷新时刷新余额。领取按钮、宣传数量和点击动作都不是到账凭据，以成功提示、已领取状态或领取前后变化为准。用户指定账号时先核对当前标识，无法匹配则停止该账号的领取并报告。
4. 本轮包含更新时，完成当前应用的打卡和活动检查，记录领取结果后再检查其官方内置更新。当天已领、没有活动入口或领取失败时，也照常检查更新。有新版就按提示安装，等待安装和必要的重启结束，再核对实际版本或更新状态。遇到正在执行的任务、未保存内容或额外权限、协议要求时，保留现场并报告阻塞。更新停滞或失败时，分别报告打卡结果和更新进度。
5. 有无领取结果都要收尾。尽力切回原账号，关闭本次新开的活动页或标签。原本未运行、由本轮启动的应用，在安全时用应用菜单正常退出并核实进程停止。工具提示窗口状态变化时先重新读取界面，按实际使用情况判断是否能退出。应用原本就在运行、用户在本轮另行打开或接手、还有任务执行或未保存内容时，保留应用运行。原本运行的应用在更新重启后未自动恢复时重新打开。
6. **优先结束对当前应用的 Computer Use 控制会话并核验**。有单应用结束操作时使用它并读回状态。按上一步正常退出的应用，可用下方的 macOS 日志核对本轮捕获。如果工具无法结束会话或缺少确认，记录「Computer Use 控制会话结束未确认」，停止对该应用的操作，继续串行处理下一款。
7. 当前应用的下载、安装、重启或已发起的退出仍在进行时，等待操作结束再处理下一款。实际操作卡住且无法安全完成时，报告具体阻塞和未完成项。按下方格式汇报本轮结果及未恢复的状态。

### macOS 捕获日志核验

使用 `cua_repl` 且已正常退出任务启动的应用时，将下列起始时间替换成选取该应用前记录的本地时间。按 `SCStream` 地址和时间配对，只采信能归于当前操作的事件。每条启动的捕获都要有随后对应的停止和销毁事件。地址重用时按各次启动分别核对。日志缺失或捕获来源混杂时，将释放状态记为未确认。

```sh
/usr/bin/log show --start 'YYYY-MM-DD HH:MM:SS' --info --debug --style compact \
  --predicate 'process == "SkyComputerUseService" AND (eventMessage CONTAINS "startCaptureWithCompletionHandler" OR eventMessage CONTAINS "stopCaptureWithCompletionHandler" OR eventMessage CONTAINS "[SCStream dealloc]")'
```

## 领取入口

- **WorkBuddy**（`com.tencent.workbuddy.mac`）默认领取「Buddy加油站」的每日积分。先读用户菜单中的积分余额，从侧栏或用户菜单进入加油站。有「立即领取」时点击一次，核实「领取成功」，再刷新菜单余额。已领取时记录当日状态。任务指定成长计划项目时，继续下方相应步骤。更新或退出前检查是否有任务正在执行，包括定时任务。有任务在跑就分段等待，出现提示时选择「等待」，确认任务结束后再继续更新或正常退出。若本次执行到达时限，保留 WorkBuddy 运行，报告待完成的更新或退出。
- **TRAE CN**（`cn.trae.app`）：左下角用户菜单 →「签到」，确认「已签到」，记录可见余额和变化。
- **Qoder CN**（`com.qodercn.app`）：从用户菜单进入「权益中心」，查看本期 Credits 活动（曾显示「每天领 100 Credits」）。活动可领取时点击「领取」，确认到账或本周期已领取；若入口未显示，按本次界面如实报告。在「我的用量」刷新并读取可用 Credits，区分套餐和资源包。跨日残留的活动窗口须先关闭重开。刷新时间和有效期按当前活动说明填写。
- **豆包工作**（`com.work.pc.doubao`，本机可用 `/Applications/DoubaoWork.app` 消除同 bundle ID 的路径歧义）：记录左下角当前账号，侧栏签到卡片 →「立即签到」，核实「签到成功」及当次卡片额度。打开账号菜单，检查主列表和「更多账号」中的已登录账号，逐个切换并确认账号标识，分别检查并签到；每个账号单独记录结果及可见的可用额度。无签到入口时如实报告；需要登录、验证或无法切换时记录具体阻塞，继续其他账号。完成后切回原账号并核实。不要添加账号或退出登录。
- **ZCode**（`dev.zcode.app`）先在当前版本的首页左下角查看「领鸡蛋」活动卡片。辅助功能树未显示卡片时查看截图。有可领 Token 时点击「领取」，核实成功提示或本期已领取状态，记录实际数量、适用模型、生效时间和有效期。未见卡片或无法核实领取结果时如实报告。宣传数量不等同于已确认领取，也不等同于账户余额。

### WorkBuddy 成长计划

从当前账号的应用内用户菜单进入「成长计划」，在同一窗口操作。按本次用户请求或排程明确包含的项目执行。

- **活跃地图和补签**。打开「本月活跃地图」，按页面图例核对今天和历史日期的状态。今日已亮就记为已活跃。尚未点亮且规则要求一次真实对话时，报告该条件，仅在已有实际对话任务授权时执行。获授权补签且有补登卡时，点明确可补登的历史日期。辅助功能树仅聚焦日期时，用截图核对图例和目标格再点击。核对选中日期和弹窗提示的卡片消耗，按「使用」一次。看到「补登成功」后重新核对日期格、剩余卡数和连登天数，再处理下一处适用缺口。
- **免费轮盘**。在每日任务中核实可用的免费抽奖次数，有次数才进入轮盘。每次点一次「START 抽奖」，读取奖品、发放状态及剩余次数。「再抽一次」返回轮盘后，按新读数决定是否继续。次数为 0 即结束。界面提示积分稍后到账时，单独记录奖品，刷新余额再核实到账。结果不明时查看奖品记录和剩余次数，核不清就结束本次抽奖。遇到付费、押注或需选择不同兑换档位时，保留选择并报告。
- **Buddy 旅行**。先看成长计划旅行卡。已有倒计时就记录当前目的地和倒计时。需要领返回礼物或派出时，复用 [buddy-travelling](../buddy-travelling/SKILL.md) 的礼物、目的地、回执和通知规则，继续操作当前 App。按上海日期读取调用方持久化的同账号回执，用该包的 `scripts/buddy_contract.py --service-day YYYY-MM-DD` 检查。仅在没有旧回执且没有同日派出线索时传入 `null`。遇到待领礼物按页面核实领取结果后关弹窗。派出须通过回执检查并看到可用的「派猫猫旅行」。用户指定地点时选唯一可用的同名项，否则沿用当前已选的可用地点。确认前核对选中项，在调用方记录中持久保存本次尝试，再点一次「确定派出」。用 `dispatch_receipt()` 核对同一旅行卡中的地点和新倒计时，保存返回的完整回执。同日已有派出尝试、回执冲突或提交后结果不明时，只核查当前旅行状态。读不到该包或无法保存尝试记录时，报告当前状态并停止派出。登录和维护通知使用调用方已有授权及该包的去重规则。

在 WorkBuddy 的报告行区分加油站到账与抽奖奖品，列出实际处理的补登日期、卡数及旅行结果。已在旅行、此前已领取等状态按进入页面时的观察报告。

## 更新入口

- WorkBuddy：用户菜单 →「检查更新」。
- TRAE CN：macOS 应用菜单 →「检查更新」。
- Qoder CN：侧栏更新状态或应用菜单；出现「安装更新」时按提示安装并重启。需核对版本时使用 macOS 菜单「Qoder CN → 关于 Qoder CN」；用户菜单中的「关于 Qoder」可能打开官网。
- 豆包工作：用户菜单 →「检查更新」或「完成更新」。
- **ZCode** 记录「领鸡蛋」结果后，查看首页左上角的更新按钮（绿色向下箭头）或应用内更新提示。核对当前版本和目标版本，窗口日期按版本发布日期记录。显示「已准备就绪」时点击「重启以更新」，等应用重新打开，读回实际版本并与目标版本核对。

以当次实际界面为准；更新后核对已是最新版、版本号或其他完成提示，只有下载中、安装中或点击操作时标为未完成。优先使用应用内入口，不为检查版本或余额打开官网；只有应用内无法核实时才使用必要的活动页面，并在离开当前应用前关闭本次新开的页面。仅处理本次范围内的领取项目和获授权的 WorkBuddy 成长计划项目，跳过其他抽奖、邀请和购买活动。

## 汇报格式

汇报只列本次任务范围内的应用。表格前注明本次执行的设备。多台机器分别核实、分别报告。表格用四列 `App | 新增情况 | 余额 / 有效期 | 打卡结果`。豆包工作每个账号单独一行。ZCode 第二列写已确认领取的 Token 和模型，第三列写生效时间及有效期。不可见或无法核实的数字写「未显示」或「未确认」，不根据旧记录推测；未在本次新增则写「本次无新增」或「未确认」，不把历史领取写成本次新增。

结果列用 ✅ 表示已确认领取成功或本周期已领取，🟡 表示无入口、未到刷新或结果未确认，❌ 表示登录、切换或操作失败。因实际阻塞而未操作的应用，新增和余额填「—」，结果列用 ⏸️ 写明具体原因。表格后的更新结果每款应用单独一行，仅领取或查询时省略更新段。另简报控制会话结束情况与账号、应用状态恢复情况。若定时触发环境要求固定外层格式，把汇报放入该格式的消息内容中。
