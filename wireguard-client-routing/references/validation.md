# 验证与交付

按本次请求选择检查，记录时间、输入/输出哈希、工具版本及是否触达服务器、密钥、网络或当前客户端。回执不含私钥或 PSK。原始结果与后来的纠正记录并存，缺哪一版原件就注明哪一版。

## 按任务确定验收范围

| 请求 | 交付与检查 |
|---|---|
| 只研究/只读核查 | 证据、结论、未解项或方案；只读访问按已有授权执行，缺访问仍继续材料研究 |
| 只生成配置 | 输入绑定、完整性、输出权限/哈希及使用说明；实际设备状态保留待验，现场网络检查记 not_requested |
| 导入/修复连接 | 受影响设备的解析、实际活动配置、路由和原故障复验；已有可用设备保持原状 |
| 性能/持续稳定性修复 | 在上述连接检查之外，先明确完整传输、时长、流量预算、网络条件及成功标准，再测所需窗口 |

范围已有明确约定就执行，不逐项再问许可。缺少关键条件只影响对应检查。Wi-Fi/蜂窝、重连/休眠和跨时段试验按用户实际故障与验收范围选取。

## 生成前后

- 检查 `targets` 与实际文件一一对应，独立设备地址和私钥不复用，服务端绑定一致。原始文件哈希保持不变。
- 核对完整国内规则数量、DIRECT 例外保留/过滤数量、海外组只含 WG、末条规则、IPv6 策略、DNS 走向和文件权限。IPv4-only 下被首条 IPv6 REJECT 覆盖的 IPv6 DIRECT 例外注明未启用；写入数量与规则可达性分开。
- 解析检查适用时，用目标相同版本 Mihomo 运行 `mihomo -t -f <private-file> -d <private-cache>`；记录实际 core/hash/构建标签。JSON 形式的 YAML 是合法 YAML。日志留私密目录，摘要脱敏。字段接受后仍需核对版本支持及实际生效路径。
- Skill 自检运行 `python3 -B scripts/test_build_clients.py`。开发期还需独立 agent 在未预告预期答案的场景中前向试用，记录遗漏和修复。离线场景推演单列，不充当设备实测。

## 测试身份与共享资源

现场测试前绑定实际执行主机、目标设备、正式/测试 peer、活动占用、core、物理出口、共享带宽组及开始/结束/取消时间。保留用户既有代理入口、活动连接和未受影响设备；同名主机或临时端口不能替代目标绑定。

临时目录、端口、进程或禁用 TUN 只隔离对应资源。沿用正式 peer 会共享其握手/endpoint 状态，跨主机测试优先使用已有授权覆盖的独立测试身份；无合适身份时保留主动测试待办，继续独立只读项。添加/重建 peer、改时钟和变更服务器均属于写入，不能作为只读诊断的隐含步骤。

记录时钟偏差。单机耗时用单调时钟，跨机顺序用控制端参考与偏差范围；时钟回退配合身份复用可作为握手故障假设，须由证据确认，不能直接认定唯一根因。不要默认重置正式 peer 来消除测试状态。

共享出口的吞吐测试安排互斥时间窗，记录其他任务和背景流量是否已知。普通文件与研究工作可并行。当前任务结束/取消后释放自己的窗口并保存清理回执；未知时间偏差或缺另一任务 raw 时，保留重叠情况未知。

## 隔离联网验证

使用私密副本、新 loopback 监听端口、临时进程与缓存；禁用 TUN，核对真实物理出口，避免套入当前 TUN。按上节核对 peer 身份，记录基线与清理后读回。普通日志不输出节点配置。

在路由验收范围内，实际请求覆盖国内域名 DIRECT、海外 HTTPS WireGuard、出口 IP 与服务器匹配、AAAA、显式 IPv6，以及故障时国内仍通而海外失败。控制器连接记录核对选中规则和节点，连同请求结果判断路径。

断线测试只修改隔离副本的端点，不关生产服务或改活动配置。负向结果以真实请求失败和对应路由/日志判定，不能使用正常成功连接标记作为唯一条件。对象不存在的404、探错端口、缺字段和环境拒绝归为测试前提/方法问题，记录实际错误并修正该检查。

测试结束终止自己的隔离进程，核对监听、peer 运行态、配置与路由/DNS。只读诊断不要求补造不存在的清理写入。临时资源写入的清理与运行态变更按 [服务器合同](server.md) 回读。

## 传输与统计

每次试验保留 `planned`、`attempted`、`skipped`、`complete_count`，并分别记录下载、上传、失败原因。前置失败后未发出的请求记 skipped；attempted 为零时速率和成功率为空。预热单列，aggregate 与逐阶段副本去重。

完整传输同时核对内层返回码、HTTP 状态、期望/实际字节和路由，按内容类型增加 Range、内容校验或服务端接收回执。固定文件可核哈希，动态测速内容按实际字节/范围验；上传只有 HTTP/客户端字节时说明其证据范围，目标要求服务端完整接收时取得服务器字节或哈希回执。外层进程退出0不覆盖内层失败，HTTP200部分下载和curl0+429分别保留为失败。

十进制 Mbps 为 `8 * actual_bytes / total_seconds / 1_000_000`，MiB 为 `1_048_576` B。全请求速率与近似正文窗口速率 `8B/(total-ttfb)/1e6` 分列；TTFB 到首响应字节，并非严格的正文开始。成功子样本中位数旁列完成数/实际次数及失败样本；包含失败的字节/请求耗时汇总注明口径，并行请求耗时之和不作为墙钟链路带宽。

每条 raw 至少绑定方法/目标、`transport_rc`、`http_status`、`expected_bytes`、`actual_bytes`、`total_s`、`ttfb_s`、路由证据、执行主机、peer、core 和配置哈希、出口、时间窗与时钟信息。TCP connect、WG握手、HTTP TTFB、URL-test 分别描述起止事件，跨网络/方法的延迟不直接相减归因。主机 TCP 计数、重复 socket 观测与业务独立样本分别统计。

短窗口改善保留为该窗口结果。慢请求、部分下载、限流和长连接失败进入总报告；例如10MB成功而50MB第二次超时，完整传输/稳定性项保留相应失败。网络根因未定位时给出下一项可区分假设的最小检查，不先更换服务商/IP或全局关闭功能。

## 目标设备与最终状态

实际设备验收包括导入与启用、合并配置/VPN设置、该 peer 的握手/计数、国内外路由，以及范围内 DNS/IPv6 和原有关键应用/LAN 的复验。原故障如微信发图需重复相应实际操作。缺设备访问标记 `pending_target_device`，桌面隔离核心测试记录其平台和覆盖。

每设备分列生成、目标核心解析、隔离路由、目标 App/VPN、完整传输、约定稳定性，使用以下状态。

| 状态 | 使用依据 |
|---|---|
| passed | 本项约定检查成功，绑定配置哈希、实际版本、方法、时间窗与原件 |
| failed | 实际执行未满足本项标准，保留失败和影响 |
| pending | 本项在范围内，但尚未执行或缺执行条件 |
| inconclusive | 已有观察不足以判定，例如测试对象异常或对照混杂 |
| not_requested | 本次请求未要求该项 |

生成回执保留脚本原有 schema；上述验收项写入人工交付报告，不能伪称生成器已经输出新字段。报告写出 adopted/candidate/rejected、supersedes 与实际活动状态，缺读回时为 unknown。本次请求所需项满足才称修复完成，其他范围外项不阻塞本次交付。

私密目录交付配置、参数参考、使用说明和输入/输出回执。普通包只交 Skill、代码、来源和脱敏报告，私密文件定位限获准接收者。提交或分享前扫描实际私钥/PSK 未进入包；凭据、真实现场绑定、运行缓存留本地。服务器变更、客户端应用和 Skill 发布分别记录实际结果。
