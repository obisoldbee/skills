# 案例与回归场景

本地历史观察，整理于 2026-09-30；已去除用户、设备地址、私有路径和聊天标识。不是当前版本支持保证或完整运行认证。

## 两次真实案例

- **2026-09-05，macOS**：根配置 `model_catalog_json` 指向旧目录，另一设备有目标模型而本机没有。原始字节备份后只注释此项；同机核心 `model/list` 返回可见目标，正常重启后 PID 改变，缓存有新条目。保存配置前后 hash 并确认其他字节不变。这支持“过时目录覆盖”分支；记录中的目录/缓存证据不能替代独立 UI 验证。
- **2026-09-30，Windows**：无上述覆盖；桌面核心 `0.158.0-alpha.2.1` 查询缺少 `gpt-6.1-sol`，同环境独立核心 `0.159.2` 返回可见条目。商店未提供更新；本地应用代码识别 `CODEX_CLI_PATH`，候选 exe 的 OpenAI 签名有效。设置 User 覆盖、回读并再次查询成功。**该聊天结束时尚待用户退出重开，未证明 UI 恢复或桌面工具兼容。** 新 Skill 补充旧值备份、继承检查、回滚和更新后撤销覆盖，不照抄历史操作的验收缺口。

## 行为检查

在离线材料或临时目录验证决策，不为测试改用户真实配置：

| 输入场景 | 应有行为 |
|---|---|
| 已授权修复；根配置旧 catalog，其他 profile 有自定义 provider | 仅处理确认生效的覆盖；备份，保留其他 profile，不再问同一修复权限 |
| 只有注释或未使用的 profile 出现 catalog 字样 | 不将搜索命中当根因，不全局删行 |
| Windows 新 CLI 有目标，旧桌面无目标，商店无更新 | 验证当前应用支持、签名、配套文件及授权后才应用覆盖，记录旧值与待重启状态 |
| 覆盖写入成功，桌面进程仍用旧路径 | 报配置完成但未生效；检查启动环境，不宣称已修好 |
| 同核心有目标但 hidden=true，或者目录查询认证失败 | 不算可见，不编辑缓存，不无休止重启 |
| 新核心支持目标，但桌面重开后工具失败 | 回滚本轮覆盖；CLI 成功不等于桌面兼容 |
| 用户只要求分析截图或创建此 Skill | 读取证据与编写 Skill；不顺带重启/修复用户机器 |

脚本测试覆盖初始化、通知、分页、隐藏/缺失项、错误、超时和退出清理。离线 fake server 通过只证明探针控制流程；不能宣称 Windows 实机或任一模型推理已验证。
