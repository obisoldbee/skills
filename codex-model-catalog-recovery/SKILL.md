# Codex 模型列表恢复

目标：找出指定设备的 Codex 为什么看不到用户指定的模型，实施有证据支持的最小修复，并验证桌面端实际结果。模型名称、版本和可用思考强度以本次目标运行时为准，不沿用历史型号清单。

## 输入与边界

- 绑定目标主机、操作系统、用户、Codex 应用、该应用实际使用的核心路径及 `CODEX_HOME`、目标模型 ID。远程工具所在设备可能不是故障设备；有多个候选时只询问缺失的选择。
- “排查原因”先只读；“帮我恢复/修好”可执行与原因对应的配置修复，复用已有授权。修复前说明具体改动和影响，不为同一授权重复询问。
- 重启会中断任务和远程连接。先检查活动任务；只有重启影响已获授权且续接方式可用才执行。若当前执行器就在待关闭应用内，先交付恢复路径，让用户退出重开或由已授权的独立执行器接续，不能假装重启后还能自行验收。
- 不修改登录凭据、项目、聊天数据库、线程锁或安全设置；不抄另一个设备的缓存或凭据。不要直接改缓存中的型号、强设默认 `model`、切换账户或降级用户指定模型来伪造可用性。

## 先收集可对照的证据

**配置优先**：先检查 `config.toml` 及它的有效覆盖来源，处理已确认的旧目录固定项；不要把“升级 CLI”当作模型缺失的默认答案。配置无异常或修正后仍缺失，再对照桌面核心与独立 CLI。若用户同时授权更新两者，分别走各自正式渠道并分别核对版本；二者同步维护有益，但不保证共用核心，也不证明故障已修复。

按 [平台诊断与恢复](references/recovery.md) 读取当前平台段。记录桌面版本、桌面核心 `--version`、独立 CLI 版本、配置生效来源及缓存时间。只提取相关字段，不输出整个配置、环境变量或日志。

重点核对：

1. `model_catalog_json` 是否实际生效，来自根配置、所选 profile、启动参数还是其他已确认配置层。用 TOML 解析区分根键、嵌套键、注释；搜索命中不等于生效。
2. 当前桌面核心与 PATH 中的 `codex` 是否同一个文件。升级 CLI 不代表桌面核心也升级。
3. 缓存中是否有目标模型，以及该条目是否隐藏。`models_cache.json` 的 `client_version` 只代表写入者，不能单凭它判断正在运行的桌面版本。
4. 必要时在同一设备、同一 Codex home、同一工作目录/账户/有效配置下，分别查询两个**已验证来源的核心**的 `model/list`。它是目录查询，不生成答案，但运行时可能联网、写缓存和日志，不能称为严格离线只读。严格只读请求下先给出已有证据，不擅自启动查询。

查询可用 Python 3.10+ 的 [probe_models.py](scripts/probe_models.py)，操作与验证层级见平台参考。先检查所选核心的实际协议；不要将诊断进程当成现有桌面进程。两次查询顺序执行并分别保留结果，防止共享缓存的最后写入者混淆结论。

## 按证据选择一个修复分支

| 观察 | 处理 |
|---|---|
| 已确认生效的自定义目录固定了旧模型集 | 备份配置，仅禁用对应覆盖项；保留自定义 provider、其他 profile、默认模型及思考强度。按参考中的字节与语义检查验证。 |
| 无目录覆盖；同环境新版核心能列出目标，桌面旧核心不能 | 优先检查桌面正式更新渠道。Windows 无更新时，只有满足参考中的来源、兼容性、备份和回滚条件，才采用 `CODEX_CLI_PATH` 核心覆盖。 |
| 目标桌面核心已经列出可见模型，菜单仍缺失 | 检查 UI 筛选/当前连接目标，再考虑正常重载或重启；不要继续改配置或删缓存。 |
| 两个核心都缺失、隐藏，或查询报认证/网络错误 | 报告实际层级，查账户、服务端发布范围或连接故障；“另一台有”不足以证明本账户已开放。不要循环重启。 |
| `unsupported reasoning effort` 或 `already has an active writer` | 前者检查该模型在该接口的参数；后者转线程运行时诊断。本 Skill 不清锁、不刷新模型来修这两类错误。 |

一次改动后查询并验收；没有改善时保留证据、恢复本轮不再需要的覆盖，依据新证据进入下一分支。没有新的区分性证据时停止重复改动，交代具体阻塞及下一步。

## 验收与输出

分别报告，不互相替代：

- **配置已修正**：备份与回滚位置、改动范围、回读一致。
- **核心可列出**：本次查询的核心路径/版本和目标 `model`，`hidden=false`；缓存只能作旁证。
- **桌面已恢复**：重启后确认实际核心路径/版本及环境生效，再直接检查目标桌面的模型菜单，或取得用户确认。未检查就写“待重启/待界面确认”。
- **实际调用成功**：只有用户要求并完成实际模型调用才报告；目录查询不证明推理调用成功。

回复说明原因、做了什么、当前达到哪层、还有什么未验证。历史案例仅作分支依据，见 [案例与回归场景](references/cases.md)，不把其中版本、路径或权限假设当作当前事实。
